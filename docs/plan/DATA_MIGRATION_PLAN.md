## 1. 真实痛点（现状 + 证据）

### 1.1 无任何数据迁移能力

RockSys 支持三方言（sqlite/mysql/postgres）运行库，但**换库、备份外迁、数据汇聚全靠手工导出导入**：

- 表同步（schema 同步）只作用于**运行库自身**：`GET /admin/db/schema` + `POST /admin/db/exec`（`internal/adminapi/dbschema.go:29-31`），期望结构来自运行期 SQLSource，无法对任意外部库执行。
- 数据层只有查询（表概览 `/admin/db/size`、SQL 历史 `/admin/db/execlog`），无跨库搬运入口。
- 换库场景（如开发 SQLite → 生产 MySQL）目前只能 mysqldump/sqlite3 .dump 等命令行工具手工拼，方言不通、无 UI、无进度。

### 1.2 地基库已备好多数据源底座，RockSys 未接入

`easydb/dsn`（`D:\projects\golang\rocksys\easydb\dsn\datasource.go`）已提供：

- `DsnGroup`：多数据源管理（增删、`ActiveCode`、按 `Name` 引用——`DataSource.Name` 注释明示「用于 ETL 任务按名引用」）；
- `dsn.DsnConf`（`dsn/conf.go`）：JSON 文件持久化（`GetDsnGroup`/`SaveDsnGroup`）；
- MySQL DSN 密码含 `@` 校验（`CheckMySQLDSNPassword`）。

RockSys 全仓无一处 import（rg `easydb/dsn` 零命中）——底座空转。

### 1.3 数据库页页签缺「数据」维度

`webui/assets/js/views/database.js:296`：页签仅 表同步（schema）/ 表概览（overview）/ SQL 历史（history），结构有了、体积有了，**数据本身无落脚点**。

### 1.4 GeoIP 同步卡错挂在「表概览」页签

GeoIP 同步卡（`database.js:420 geoSyncHTML`，`overviewHTML()` 末尾 `database.js:414` 挂载）语义是**数据维护工具**而非「表结构概览」，与页签主题不符；用户定调移入新「表数据」页签并更名「GeoIP 数据同步」。

### 1.5 长任务被 HTTP 超时压制，且无统一承载

- GeoIP 同步、SQL 手工执行（`/admin/db/exec`，页内报「请求超时（15 秒），可缩小范围或稍后重试」）、未来的数据迁移，全是可能超 15 秒的长任务，却都以同步 HTTP 请求承载——超时即断，前端拿不到结果也看不到进度。
- 三类任务各自为政，无统一的创建/查询入口与互斥约束，代码行为发散。

## 2. 需求（本方案要达成的目标）

1. 数据库页新增「表数据」页签，顺序：表同步 → 表概览 → **表数据** → SQL 历史（用户指定）。
2. 数据源配置（底座 = `easydb/dsn`）：增删改查外部数据源（三方言驱动），连通测试，持久化。
3. 选定迁移目标后，**复用已有表同步链路**对目标库对齐表结构（三方言内嵌 SQL 源现成）。
4. 数据迁移（仿 Kettle 表输入→表输出模型）：同名字段跨方言直迁，默认 **1000 行/批**；批次大小存内存、可临时修改、**不持久化**（重启恢复默认 1000）。
5. GeoIP 同步卡移入「表数据」页签，更名「GeoIP 数据同步」；同步执行改造为后台任务模式（D19）。
6. 通用 ETL 方案规划：模型上源/目标皆可为任意数据源，本期落地范围与边界明确（见 §4.9）。
7. 新增**任务执行中心**后端模块：数据迁移、GeoIP 同步、结构对齐执行、SQL 后台执行等长时间任务统一注册/查询（D20–D29），仅内存、不持久化、不做独立前端 UI。
8. GeoIP 同步与数据迁移共用同一套前端进度交互组件，摆脱 HTTP 超时限制（D19）。

## 4. 设计方案

### 4.0 数据结构与数据流（数据设计总览，宪法 §7）

> 本方案**无新增数据库表**：数据源是运行资产而非业务数据，存 JSON 文件（D11）；迁移任务状态存内存（D12）。故 `docs/DATA_DICT.md` 无变更，此处按宪法 §7 阐明文件型数据结构与全局配置项。

**全局配置项（easyconf 注册，唯一新增）**

- `CONF_DIR`：全局统一配置目录，字符串，默认 `conf`（相对工作目录，开发规范下即 `bin/conf/`）；经 `conf.Manager.Register` 注册（title/usage 注明目录语义与 `dsn.json` 位置），`default.env` 随装配自动同步。生效语义：每次读写数据源文件时**实时取 `CONF_DIR` 当前值**拼接路径（支持热更）；变更后原位置的 `dsn.json` **不自动搬迁**——需手工移动，否则按新位置视为全新空配置（已知边界，§8）。

**数据类型（`<CONF_DIR>/dsn.json`，由 `dsn.DsnConf` 序列化；懒创建——首次写入时目录/文件不存在则新建）**

```json
{
  "ActiveCode": "<md5(dsn)>",
  "DsnList": [
    { "Code": "<md5(dsn)>", "Name": "prod-mysql", "DriverName": "mysql", "Dsn": "user:pass@tcp(host:3306)/db" }
  ]
}
```

- `Code` = `md5(Dsn)`（`dsn` 包生成，唯一定位）；`Name` 人工连接名（唯一，迁移目标按名引用）；`DriverName` ∈ {sqlite, mysql, postgres}（须为已注册驱动）；`Dsn` 完整连接串（含密码，本机明文，UI 脱敏展示）；`ActiveCode` 由底座维护（首次追加自动激活），本方案按 Code/Name 引用、**不依赖激活态**。

**数据关系**：数据源 ↔ 迁移任务 = 按名/按 Code 引用（无外键，JSON 文件与内存任务解耦）；迁移目标库的表结构 ← 内嵌 SQL 源（与运行库表同步同源）。

**数据流转**：① CRUD 端点写 `<CONF_DIR>/dsn.json`（`SaveDsnGroup` 原子写：临时文件 + rename 替换，写中途崩溃不留半截文件）；② 表结构对齐：读运行库同款 SQLSource → 对目标库 diff → 生成 DDL → 目标库执行；③ 数据迁移：源库流式 SELECT → 内存攒批（默认 1000 行）→ 目标库事务批量 INSERT → 循环至游标尽；④ GeoIP 数据同步：数据流不变（现状 `geoSyncAll`）。

### 4.1 页面：「表数据」页签（`views/database.js`）

- `state.tab` 新增 `'data'`，页签顺序 `schema → overview → data → history`（`database.js:296` tabsHTML 数组插入）；`state.geo` 状态随卡迁入 data 页签。
- 页签内**自上而下按迁移流程排列**四卡（对应「先数据源配置 → 选迁移目标 → 结构对齐 → 数据迁移」）：
  1. **数据源**卡：列表（名称/类型/DSN 脱敏）+ 添加（名称、驱动下拉三方言、DSN、连通测试按钮）+ 删除；连通测试独立按钮（`POST /admin/db/dsn/test`，ping + 版本号回显）。
  2. **表结构对齐**卡：下拉选迁移目标（数据源之一）→「检查差异」（diff 项 + 生成 DDL 预览，复用表同步页的展示形态）→「执行对齐」（逐条执行、遇错停、结果回显；执行前确认弹窗）。
  3. **数据迁移**卡：源（默认「本机运行库」，可切数据源）+ 目标（数据源；**不可选运行库**，下拉中不出现）+ 表清单（多选，来源=期望结构业务表）+ 批次大小输入框（默认 1000，本次会话内存态，改后不落盘；输入框备注，D17：「默认 1000 行/批，性能参考值：批越大吞吐越高，内存占用与目标库单语句负载也越高；超出目标库参数上限时服务端自动切分执行，无需手工计算」）+ 冲突策略（清空重灌/跳过冲突）→「启动迁移」→ **表级进度区**（D12）：每张表一行——状态（待迁移/迁移中/已完成/失败/已取消）+ 行数进度（已迁/总）；**待迁移**状态的表带单表取消按钮（从本次任务移除）；另设整任务取消按钮（当前批次事务完成后停止）；全局互斥（有任务在跑时启动按钮禁用并提示）。
  4. **GeoIP 数据同步**卡：整卡自表概览页签移入（`geoSyncHTML` 调用点从 `overviewHTML()` 移至新 `dataHTML()`），标题「GeoIP 同步」→「GeoIP 数据同步」；按钮、确认弹窗、端点、断点续填逻辑零改动。
- UX 红线照旧：load fetch 透传 `opts`（含 `silent`）；非引导态失败弹 `Rock.ui.toast(msg,'error')` 不自动消失；文案三要素。

### 4.2 数据源管理端点与存储（`internal/adminapi/dsn.go` 新增）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/admin/db/dsn` | GET | 列数据源（DSN 脱敏：mysql/postgres 保留 `user@host/db` 形态摘要；sqlite 为文件路径、不含凭据，原样展示） |
| `/admin/db/dsn` | POST | 添加：`{name, driver, dsn}`；校验驱动已注册 + `Name` 唯一 + DSN 重复拦截（`appendDsn` 内建：同 DSN 即同 Code，重复添加报错）+ MySQL 密码 `@` 预检（复用 `dsn.CheckMySQLDSNPassword`）+ 可选立即 ping |
| `/admin/db/dsn/delete` | POST | 按 `code` 删除（该数据源有迁移任务进行中时拒绝） |
| `/admin/db/dsn/test` | POST | `{driver, dsn}` 连通测试（`sql.Open`+`Ping`+版本查询；不落盘，可直接测试未保存的 DSN） |

- 存储：`easydb/dsn.NewDsnConf(<CONF_DIR>/dsn.json)`——路径每次读写时按 `CONF_DIR` 当前生效值拼接（D11，支持热更）；**不用 `dsn.GetDsnConf`**（其内部 `sync.Once` 单例会把首次实例永久复用，路径锁死首值，与热更语义冲突）；写入走 `SaveDsnGroup`；**懒创建**：首次写入时目录/文件不存在则新建（读取时不存在视为空 `DsnGroup`，不报错）。
- 模块归属：数据源为管理面资源，handler 放 `internal/adminapi/dsn.go`，存储包装同文件（`internal` 不 import `plugins`，无越界）。

### 4.3 目标库表结构对齐（复用表同步链路）

- 复用点：`db.Open(targetDriver, targetDsn)`（`internal/db/db.go:108`）为**目标库**开 `*db.DB`——**不传 ScriptHub**：hub 对同名子目录只允许注册一次（`internal/hotswap/hub.go:101`，防装配缺陷的刻意设计），运行库启动时已注册 `sql/`，目标库再传同一 hub 必然 Open 失败；不传时 `DB.SQL()` 走 `ScriptDir` 直读（`internal/db/db.go:195`），读取语义与运行库**同源**（外挂优先、内嵌兜底，同一份内嵌 FS 与外挂目录），仅无缓存与热更订阅——对低频运维动作无影响。「同源」靠读同一份脚本文件达成，而非共享 hub 实例。`DiffSchema(ctx, targetDB, specs)` + `GenerateSQL`（`internal/db/schema_diff.go:236/381`）原样复用——现有链路本就按 `DB.driver` 分方言，目标库连接换入即用。
- `specs` 来源与运行库表同步一致（同 SQLSource 解析），**保证迁移双方结构同名同义**。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/admin/db/migrate/schema` | GET | `?code=<数据源>`：目标库 diff 预览（items + 生成 DDL 文本，只读） |
| `/admin/db/migrate/schema_apply` | POST | `?code=`：对目标库逐条执行 DDL（拆句、遇错停、逐条结果回显——照 `/admin/db/exec` 模式）；执行经任务执行中心后台化（§4.6 接入点 3，防长 DDL 超 15 秒 HTTP 超时）；**不写运行库 `sql_exec_log`**（D14：目标库动作不属于运行库审计域，结果在响应与任务进度展示） |

### 4.4 数据迁移执行器（`internal/adminapi/migrate.go` 新增）

- **执行模型**：后台执行统一经任务执行中心（§4.6）提交；全局单任务互斥由中心承担（D12/D20）；context 取消支持；进度快照原子读。
- **读（表输入）**：源连接读 `SELECT * FROM <table>`（`rows.Next()` 逐行迭代、攒批即写，**应用层内存占用与表行数解耦**，只与批次大小相关；无 OFFSET 翻页、不依赖主键形态）；`rows.Columns()` 取源列名。注：PG/MySQL 协议下服务端仍会物化/推送完整结果集，超大表的源库侧影响见 §8 边界。
- **攒批（Kettle batch）**：累计 `batchSize` 行（默认 1000；请求参数临时传入，服务端 clamp 100–10000，内存态不落盘——D5）。
- **写（表输出）**：目标库**同名列**批量 `INSERT INTO t (col,…) VALUES (…),…`，每批一个事务（批次 = 事务粒度）；源有而目标无的列 → 报错终止该表并提示「先执行表结构对齐」；类型经 `database/sql` 原生传递（时间/字节/数值由驱动双方方言自适应，D6 同名字段直迁）。
- **占位符预算与切子批**（D17）：参数化 INSERT 的占位符数 = 列数 × 行数，三方言硬上限为 SQLite 32766、PG/MySQL 65535（协议 16 位计数），批次过大必撞限整批报错，且单纯下调批次上限治不了标（33 列 × 1000 行即超 SQLite）；执行器按预算常量 `migratePlaceholderBudget = 30000`（三方言通用、留余量）自适应切子批——子批行数 = 预算 ÷ 列数（至少 1 行），每子批一条参数化 INSERT、**共享同一事务**，事务边界/取消/进度语义不变，用户无感知。
- **自增序列重置**（D18）：每表数据迁完（done）后，将目标库该表自增序列重置为当前 max(id)——SQLite 更新 `sqlite_sequence`、MySQL `ALTER TABLE … AUTO_INCREMENT`、PG `setval`；仅对含整型自增主键的表执行，无自增主键的表（如 `geoip_list` 文本主键）自动跳过。缺失此步时换库后首批写入即主键冲突（目标库序列停在 0 或旧值）。
- **冲突策略**（D13）：`replace` = 写前清空目标表（MySQL/PG `TRUNCATE`、SQLite `DELETE FROM`）；`skip` = 冲突行跳过（MySQL `INSERT IGNORE`、SQLite/PG `ON CONFLICT DO NOTHING`）。
- **表级进度与取消**（D12）：启动时预查各表 `COUNT(*)`（粗总行数）；进度按表快照——每表 `{name, status: pending/running/done/failed/cancelled, rowsDone, rowsTotal, err, 起止时间}`；**单表取消**仅对 `pending` 状态生效（从任务队列移除），**整任务取消**= 当前批事务完成后停止、剩余表全部置 `cancelled`；单表失败**不中断**后续表（结果汇总回显，仿 Kettle 步骤级错误报告）。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/admin/db/migrate/start` | POST | `{source:"self"\|"<dsnCode>", target:"<code>", tables:[…], batch:1000, mode:"replace"\|"skip"}`；校验目标≠运行库、任务互斥、表清单非空 |
| `/admin/db/migrate/status` | GET | 任务状态：idle/running/done/failed/cancelled + **表级明细数组**（每表状态/行数进度/错误） |
| `/admin/db/migrate/cancel` | POST | `{table?}`：带 `table` = 取消该**待迁移**表（仅 pending 可取消）；不带 = 取消整个任务（当前批事务完成后停止，已写入行保留——重跑即幂等续接） |

### 4.5 批次大小语义（D5/D17）

- 默认值 = 代码常量 `migrateDefaultBatch = 1000`；仅存于任务请求与任务内存态；UI 输入框默认填 1000、可改、刷新页面复位；**不注册 easyconf、不落任何文件**（明示边界：重启后一切恢复默认）。
- 批次是**事务粒度与性能参数**，其数值本身无撞限风险：单条 INSERT 的占位符上限由服务端按预算自动切子批兜底（D17），用户无需按表宽手工计算。

### 4.6 任务执行中心（D20–D29，新模块）

- **定位**：长任务（数据迁移、GeoIP 同步、结构对齐执行、SQL 后台执行）的统一注册与观测入口，**约束代码行为**——任务创建只有一个口（Submit），进度/状态查询只有一个口；业务逻辑留在各自模块，中心不感知迁移/同步细节，保持克制、零业务耦合。**健壮性收口同为中心职责**（D23/D24）：Run 的 panic 兜底、互斥的必然释放、终态记录的有限保留——业务写错不拖垮中心，一个任务异常不锁死全部任务。
- **实现形态**：`internal/taskcenter` 新包，纯内存（`sync.Mutex` + map + 运行中 goroutine），**不持久化、无 easyconf 配置项、无前端页面**；重启即失效（重跑幂等，同 §8 边界语义）。终态任务（done/failed/cancelled）仅保留**最近 100 条**（常量），新终态落定即淘汰最旧（D24），防常驻进程内存与 List 结果无限增长；running 永不淘汰。
- **任务元数据（最小集，D21）**：

  | 字段 | 说明 |
  |---|---|
  | `ID` | 中心生成：`{启动纪元}-{自增序号}`（纪元 = 进程启动 Unix 秒，D26）——重启后纪元变化，旧 ID 必然查不到，杜绝序号复用命中不相干的新任务 |
  | `CreatedBy` | 提交来源标识（如 `migrate` / `geoip_sync` / `sql_exec` / `schema_apply`） |
  | `Title` | 人类可读标题（如「数据迁移 self→prod-mysql」「GeoIP 数据同步」） |
  | `Progress` | 业务自填的进度描述（迁移传表级结构化明细，SQL 执行可传已执行条数等，中心只透传不解释）；**写协议 = 整体快照替换**（D25）：业务经 setProgress 每次传入不可变新快照，中心原子指针存取，禁止共享可变结构 |
  | `Status` | `running / done / failed / cancelled`（提交即 running；无排队态——全局互斥在提交口拒绝；**终态一经落定不再变更**，取消与自然结束的竞态由中心按时间先后裁定，D27） |
  | `Result` | 错误信息或补充说明（成败摘要、耗时、错误明细；panic 收口的任务落 panic 摘要，D23） |
  | `CreatedAt` / `FinishedAt` | 中心自动记录的创建/结束时间（running 时 FinishedAt 为零值）——任务耗时与「已运行多久」不依赖业务自填，Progress 长时间不动时判断慢/卡死的排查依据（D21） |

- **接口（Go 侧，仅此几个）**：
  - `Submit(spec{CreatedBy, Title, Run func(ctx, setProgress) error}) (id, error)`——**全局同一时刻仅 1 个任务**（沿用 D12 互斥语义并扩展到全部任务类型）：已有任务 running 时拒绝，返回「任务进行中，请勿重复提交」（含进行中任务的 ID/Title，供前端指引）。**收口保证（D23）**：中心在任务 goroutine 内以同一 `defer` 完成三件事——recover Run 的 panic、裁定终态（Run 返回 nil → done；返回 err → failed；panic → failed 且 Result 落 panic 摘要与堆栈首行；取消先于自然结束 → cancelled）、释放互斥；正常/出错/panic/取消全部路径必然走同一收口，业务任何写法都锁不死中心；
  - `Get(id)` / `List()`——返回快照（Progress 原子读）；Get 不存在的 ID 返回未找到（HTTP 层 404，D26）；List 含 running 与保留期内的终态任务、按 ID 倒序，元数据含时间字段透出（前端展示耗时/已运行时长）；
  - `Cancel(id)`——context 取消，各任务自行落点（迁移=当前批事务完成后停，GeoIP/SQL=语句边界停止）。**竞态语义（D27）**：Cancel 送达时任务已终态 → 不报错，返回该终态并附提示（如「任务已完成，无需取消」）；不存在的 ID（含已被 D24 淘汰的终态）与 Get 一致一律 404（D26/D28）。
- **HTTP 端点（adminapi 薄封装，D28）**：

  | 端点 | 方法 | 说明 |
  |---|---|---|
  | `/admin/tasks` | GET | 任务列表（含进行中，供前端轮询、互斥提示与页面恢复 D29） |
  | `/admin/tasks/{id}` | GET | 单任务详情（Progress/Status/Result/时间字段）；不存在 → 404 |
  | `/admin/tasks/{id}/cancel` | POST | 统一取消（D28）：context 取消 + D27 竞态语义；不存在的 ID → 404 |

  > 路由脱离 `/admin/db` 前缀：任务中心是全局模块而非数据库域专属，未来非 db 长任务接入不改路径。

- **四个业务接入点**（提交即返回任务 ID + 前端轮询）：
  1. **数据迁移** `/admin/db/migrate/start`：内部改为向中心 Submit（表级进度写入 Progress）；原 `/migrate/status` 保留为表级明细的便捷视图（转发中心快照），`/migrate/cancel` 转发中心 Cancel。
  2. **GeoIP 同步** `POST /admin/db/geoip_sync`（D19）：原实现同步等待、受 15 秒 HTTP 超时压制；改为 Submit 后台执行，立即返回任务 ID，前端轮询 `/admin/tasks/{id}` 展示进度；geoip 数据处理逻辑零改动。
  3. **表结构对齐执行** `/admin/db/migrate/schema_apply`（D22）：长 DDL 必超 15 秒，**一律任务化**——提交即返回 ID，逐条执行结果归入 Result，轮询取结果。
  4. **SQL 手工执行** `/admin/db/exec`（D22 混合模式）：**默认保持同步直返**（现状体验与响应结构不变，短语句零额外交互成本）；执行框旁提供「后台执行」开关，勾选后提交任务中心、立即返回 ID，前端经共用轮询组件取逐条结果——长语句摆脱 15 秒 HTTP 超时，短语句不被拖进「提交→轮询」。同步执行不占任务互斥（其天然受 HTTP 超时约束）。
- **前端共用组件**：数据迁移卡、GeoIP 卡、结构对齐执行、SQL 后台执行共用同一套「提交 → 轮询 → 进度/结果展示」交互组件（提取为 `webui/assets/js/` 内公共函数），实现一处、四处复用；组件含**页面恢复**职责（D29）——各卡加载时查 `/admin/tasks` 列表，存在 `CreatedBy` 匹配本卡且 running 的任务即恢复进度区续上轮询（任务 ID 不落前端存储，切页签/刷新不失联）。

- GeoIP 数据处理逻辑、断点续填机制零改动（D7）；仅执行方式任务化（D19），端点语义变更同步文档。

## 5. 验收标准

1. 「表数据」页签按序落位（表同步→表概览→表数据→SQL历史）；GeoIP 卡在表数据页签内、标题「GeoIP 数据同步」、数据处理行为与现状一致，且执行为后台任务模式（提交即返回、轮询进度，全程无 HTTP 超时报错，可用大于 15 秒的同步场景验证）；表概览页签不再含该卡。
2. 数据源管理：三方言 DSN 可增删查（DSN 脱敏展示）、连通测试返回版本；`<CONF_DIR>/dsn.json` 持久化且重启后保留（默认 `CONF_DIR=conf` 即 `bin/conf/dsn.json`，首次写入自动建目录与文件；改 `CONF_DIR` 后位置随生效值变化）；`Name` 重复、DSN 重复、未注册驱动、MySQL 密码裸 `@` 均被拦截并给出指引文案。
3. 表结构对齐：选目标库（三方言各验一）→ 检查差异与 DDL 预览正确 → 执行后目标库结构与运行库表同步结果一致（比对 diff 复检为空）；执行结果逐条回显，遇错停且可重试。
4. 数据迁移：SQLite→MySQL、MySQL→PG 至少各一真实双库用例——结构对齐后迁移，行数一致、抽样字段值一致（时间/字节/数值类型各覆盖）；批次 1000 默认生效，临时改批（如 7）行为正确且刷新后复位 1000；30 列以上宽表 × 10000 大批次不触发占位符上限报错（自适应切子批生效、数据完整）；`replace` 重灌与 `skip` 跳过冲突行为正确；**自增序列重置生效**（D18：迁移后向目标库补写一条新记录，主键 = max(id)+1 不冲突；无自增主键的表如 geoip_list 不受影响）；**表级进度实时可见**（每表状态与行数进度）、**单表取消**（仅待迁移表）与**整任务取消**生效；单表故意失败不阻塞后续表并汇总报错。
5. 互斥与防护：任务运行中再启动被拒并提示（数据迁移、GeoIP 同步、结构对齐执行、SQL 后台执行各任务类型共享全局互斥，提示含进行中任务 ID/Title）；目标=运行库被拒；运行中数据源不可删除。
6. **任务执行中心**：各任务提交后均立即返回任务 ID；`/admin/tasks` 与 `/admin/tasks/{id}` 可查询元数据（ID/CreatedBy/Title/Progress/Status/Result/CreatedAt/FinishedAt——终态耗时与 running 已运行时长可展示），不存在的 ID 返回 404；`POST /admin/tasks/{id}/cancel` 可取消进行中任务（GeoIP 同步与 SQL 后台执行各验一例：取消后状态落 cancelled、互斥立即可再获取），对不存在 ID 取消返回 404、对已终态 ID 返回终态不报错（D27/D28）；**页面恢复**：任务进行中刷新页面或切页签返回，进度区经 `/admin/tasks` 列表恢复并续上轮询（D29）；进行中重复提交被拒并提示「任务进行中，请勿重复提交」；**健壮性专项**：构造 Run 内 panic 的任务 → 状态落 failed（Result 含 panic 摘要）且互斥立即可再获取（新任务可正常提交）；终态任务超 100 条后最旧被淘汰；Cancel 与自然完成竞态时返回实际终态、不报错；重启后任务记录清空（内存语义）；SQL 手工执行勾选「后台执行」后长语句（构造 >15 秒用例）不再报 HTTP 超时、经任务查询拿到逐条结果，不勾选时行为与现状一致。
7. `go build -tags dev` / `go vet ./...` / `go test ./...` 全绿；前端改动开浏览器实看并截图留证（含数据源 CRUD、结构对齐、迁移全程与表级进度/取消、GeoIP 卡新位置与任务化交互）。
8. 文档同步：webui.md / webui-api.md / CONFIGURATION.md（CONF_DIR）/ README.md 逐项核对更新。

## 6. 决策取舍与备选（讨论留痕）

> 把「为什么这么选」的备选与理由留档（宪法 §0：会话记忆易失）。疑虑 Q1–Q8 与占位符上限议题已于 09-14 全部拍板，结论见 §3 决策表 D9–D17。

| 议题 | 曾评估的备选 | 选定 | 理由 |
|---|---|---|---|
| 迁移方向 | 仅运行库→外部 / 任意↔任意 | 通用模型 + 默认源=运行库（D9） | 主场景是换库迁移；通用模型只多一个源下拉，执行器本就面向任意连接；目标禁=运行库防误覆盖生产数据 |
| 结构对齐来源 | 内嵌期望结构 / 读源库结构克隆 | 内嵌（D10） | 三方言 SQL 源现成、复用表同步零改造，需求「复用已有表同步」字面即此；结构克隆需跨方言类型映射器，属 Kettle 完全体，边界外 |
| 数据源存储 | JSON 文件 / 入库表 / easyconf | JSON 文件 `<CONF_DIR>/dsn.json`（D11） | `dsn.DsnConf` 现成；入库有换库自举问题；easyconf 是静态键值不适动态列表；`CONF_DIR` 统一目录语义由用户定调 |
| 分页方式 | OFFSET 翻页 / 主键游标 / 流式游标 | 流式游标 | 无 OFFSET 深翻页退化、不依赖主键形态；database/sql 三方言驱动天然支持 |
| 冲突策略 | 仅 replace / 仅 skip / upsert 覆盖 / 增量差分 | replace+skip 两档（D13） | upsert 覆盖语义歧义、增量差分无统一增量键；两档覆盖换库与补数两主场景 |
| 任务持久化 | 任务表落库 / JSON 进度 / 纯内存 | 纯内存（D12） | 重跑幂等使断点续传非必需；落库为低频运维工具引入常驻表，过度设计 |
| 取消粒度 | 仅整任务 / 表级 | 表级 + 整任务（D12） | 大任务中单表发现问题可精准剔除，不必整单重来；实现仅是队列标记，增量小 |
| 执行归属 | plugins 新挂件 / internal/adminapi | internal/adminapi | 管理面单次运维动作，非数据面常速能力，不挂插件链、不占组件开关 |
| 占位符上限 | 下调批次上限 / 逐行 INSERT / 预算切子批 | 预算 30000 切子批（D17） | 下调上限治不了标（33 列 × 1000 行仍超 SQLite 32766）；逐行写丢失批量吞吐；切子批保留参数化安全与批次事务语义，用户无感知 |
| GeoIP 超时治理 | 调大 HTTP 超时 / 前端分段请求 / 后台任务化 | 后台任务化 + 共用进度组件（D19） | 调大超时治标且拖累全局请求；任务化一次到位，迁移已有同款交互，共用组件边际成本最低 |
| 长任务承载 | 各业务各自后台 goroutine / 统一任务执行中心 | 统一中心（D20–D29） | 长任务（迁移/GeoIP/SQL 执行等）同病同治；统一创建与查询入口约束代码行为，互斥与提示逻辑一处实现；中心仅元数据透传，不耦合业务 |
| 中心互斥粒度 | 按任务类型各自互斥 / 全局单任务 | 全局单任务（D20，扩展 D12） | 三类任务均压同一运行库/数据面，全局串行最克制且语义最简单；运维工具场景无并发诉求 |
| panic 与互斥收口 | 业务自查不 panic / 中心统一 recover | 中心 defer 统一收口（D23） | 互斥释放是中心生命线：业务一处 panic 即永久锁死全部任务，兜底放业务侧等于没兜底 |
| 终态任务保留 | 无限保留 / TTL 过期清理 / 固定条数淘汰 | 最近 100 条（D24） | 常驻网关长期运行，无限保留则内存与 List 只增不减；TTL 需定时器与时间基准，固定条数最简且够用 |
| SQL 执行承载 | 全量任务化 / 混合模式 | 默认同步直返 + 「后台执行」开关（D22 修订） | 全量任务化把毫秒级查询也拖进提交-轮询交互且受全局互斥牵连；显式开关由用户按语句预期时长自选，确定性最高 |
| 任务端点路由 | `/admin/db/tasks`（随数据库域收敛）/ `/admin/tasks` | `/admin/tasks`（D28） | 中心是全局模块而非 db 域专属，挂 db 前缀名实不符；未来非 db 任务接入即免改路径 |

- **工程化**：复用表同步链路与 `easydb/dsn` 底座、零外部新依赖、无新表（DATA_DICT 无变更）；唯一新增配置项 `CONF_DIR`（全局配置目录，一处注册）；任务执行中心纯内存、元数据最小集、创建/查询单一入口、panic 收口与终态限量保留（D20–D29），各长任务统一承载且单任务异常不锁死中心；三方言测试用例齐备。

## 8. 验收结论与已知边界

> 本节待实施与终验后回填。

**已知边界（设计期已定，终验核对）**
- 迁移任务状态不持久化：服务重启后进行中任务的进度丢失，需重新发起（重跑幂等，无数据损坏风险）。任务执行中心同为纯内存（D20）：全部任务（迁移/GeoIP/SQL 执行）记录重启即清空，重启期间被中断的后台任务随之终止。
- 终态任务记录仅保留最近 100 条（D24）：更早终态记录淘汰后不可再查；running 永不淘汰；任务 ID 带启动纪元（D26），重启后旧 ID 一律 404、不会命中新任务。
- 批次大小重启复位 1000（用户明示语义）。
- 源有而目标无的列触发该表失败（提示先结构对齐），不做自动建列。
- `<CONF_DIR>/dsn.json` 含 DSN 明文密码：本机文件与 `bin/.env` 同级安全边界，不入库不入 git（bin/ 已在忽略约定内）。
- `CONF_DIR` 变更后原位置 `dsn.json` 不自动搬迁（需手工移动，否则按新位置视为空配置）。
- 表清单来源=期望结构业务表：源库中不在期望结构的表不参与迁移（边界内语义，页面文案注明）。
- 源库读侧：应用层逐行流式（内存占用与表行数解耦），但 PG/MySQL 协议特性使服务端仍会物化/推送完整结果集——超大表迁移需评估源库侧内存与连接占用（本期不做游标式真流式与分页降级）。
