## 3. 设计方案（v2：拆分而非桶化分位数）

### 3.1 指标重新归属（拆分后）

| 指标 | 去向 | 口径 |
|---|---|---|
| 实时 QPS | 运行指标卡（留） | 内存窗口，window 可切 1m/5m/15m/1h |
| 实时错误率 | 运行指标卡（留） | 同上（纯计数，跨桶相加零误差） |
| **延迟 P50/P95/P99** | **迁入流量统计区**（新瓦片） | **SQL 精确分位数**：所选时间范围内 access_log.total_ms |
| 错误率（4xx/5xx 率） | 流量统计区已有 | 删除运行指标卡的重复瓦片 |
| 运行时间 | 资源信息条（见 3.3） | /admin/system 不变 |

核心收益：**原方案最难的部分（跨桶分位数直方图近似）整体废除**——运行指标只剩纯计数，跨桶相加即精确值；延迟分位数从近似变精确。

### 3.2 后端

- `GET /admin/metrics?window=1m|5m|15m|1h`（缺省 1m 兼容；非法 400）：obs metrics 桶化 1h=60×1min，聚合输出 qps（=窗口计数/窗口秒）与 error_rate（纯计数聚合，**不再输出 p50/p95/p99**——响应字段删减属破坏性变更，前端同步改，WebUI 单页交付无外部消费者）。
- `traffic_summary.sql`（三方言）扩列 `lat_p50/lat_p95/lat_p99/lat_avg`（对 total_ms；范围过滤沿用现有 from/to）：
  - PG：`percentile_cont(0.95) WITHIN GROUP (ORDER BY total_ms)`
  - MySQL 8：窗口函数或 `ORDER BY total_ms LIMIT 1 OFFSET n` 子查询
  - sqlite：`ORDER BY total_ms LIMIT 1 OFFSET n` 子查询
  - 空表防护：无行时输出 NULL，前端显示"—"

### 3.3 前端首页信息架构（重排）

```
┌ 网关信息横条（现状不动）
├ 运行状态卡（合并原「运行指标」+「资源监控」，消除高度差）
│   ├ 瓦片：实时 QPS（窗口可切 1m/5m/15m/1h chips）· 实时错误率 · 运行时间
│   ├ 趋势图（前端采样，D14 不动）+ 资源信息条（进程内存/Goroutines/核心数，
│   │   CPU/内存进度条——支持则显示，不支持则一行灰色说明）
├ 流量统计区（现有）
│   └ 瓦片区新增：延迟 P50/P95/P99（SQL 精确值，随所选时间范围）+ 平均延迟
├ HTTP 数据流（现状不动）
└ 服务状态总览（现状不动）
```

- 资源监控从独立卡降为运行状态卡内的**资源信息条**：紧凑单行/两行，消灭大片空白；系统级采集不支持的提示收敛为条内灰色小字。
- 错误率瓦片从运行指标卡移除（流量统计已有），运行指标卡从 6 瓦片瘦身为 3 瓦片。

### 3.4 已知边界

- p95 等**不再有实时 1 分钟口径**——实时性换精确性（用户定调 M2）；看"最近的分位数"可在流量统计切"近 24 小时/今日"。
- `/admin/metrics` 响应删减 p50/p95/p99 字段（无外部消费者，WebUI 同步改）。
- 内存窗口重启清零语义不变（沿用 WAF 卡副标注样式）。

## 6. 实施记录（2026-09-09，方案经用户确认后实施）

- 后端：obs metrics 1h=60×1min 桶化（纯计数，直方图方案废除）；`/admin/metrics?window=1m|5m|15m|1h`（缺省 1m），响应删 p50/p95/p99、增 window/window_seconds。
- SQL：traffic_summary 三方言扩 lat_avg/lat_p50/lat_p95/lat_p99（PG percentile_cont；MySQL/sqlite PERCENT_RANK 窗口函数最近秩——sqlite 不支持 OFFSET 表达式，OFFSET 子查询方案被否）；参数统一 26 参。
- 前端：运行状态卡（运行指标+资源监控合并，窗口 chips + 3 瓦片 + 采样趋势 + 资源信息条）；流量统计区新增延迟 P50/P95/P99/平均瓦片；chart.js 新增 bar 组件并收敛 waf.js 约 60 行内联柱状图（架构欠账清偿）。
- 验证：go test ./.../vet 全绿（metrics 窗口滑动/双窗口单测、traffic 三方言含真库门控全过）；浏览器实测截图核验（运行状态卡布局无高度差、窗口切换、延迟瓦片出数、柱状图标签正常）。
- 延迟对账：本地样本 [0,0,0,0,1,169] → avg=28 / p50=0 / p95=1 / p99=1，与手工 PERCENT_RANK 计算一致。

## 7. 修订（2026-09-09，用户审查后调整）

用户指出：延迟 P50/P95/P99 在**小时间尺度**（1m/5m/15m）同样关键——能立刻发现"是不是出问题了"，只留大范围 SQL 口径会丢掉实时发现能力。据此修订 M2：

- **恢复**运行状态卡延迟 P50/P95/P99 瓦片，随窗口切换（1m/5m/15m/1h）；
- 实现弃用直方图近似，改**每分钟桶水库采样**（每桶均匀保留 ≤200 个 total_ms 样本，60 桶内存上界约 96KB），合并样本最近秩分位——近精确、无直方图桶界误差；
- 流量统计区的 SQL 精确分位数保留：实时近似（小窗口秒级发现）与范围精确（长周期分布）互补，口径在标签中标注。
