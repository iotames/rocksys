## 4. 红线摘录（执行期必守，来源见上层决策表与仓库法）

- 请求路径零锁零阻塞：快照经 `atomic.Value` 原子替换，排空仅限 Stop/Rebuild 阶段健康检查资源（S5）。
- 既有 dispatch 测试（旧 DSL 语义）回归必须零改动全绿（G5）；任何解析器/匹配改动先跑该组用例。
- DB 可用时规则表为唯一源，禁止回看旧 DSL 合成（S4）；`DISPATCH_ENABLED` 仍为总开关。
- 数据层红线：新表三方言脚本 + DATA_DICT + Go 枚举三处同步，缺一即违规；公共字段 UTC 惯例与既有表一致。
- WebUI 红线：toast 唯一组件（§4.10）、服务端报错必弹 error toast、DB 未就绪 503 属普通错误非引导态、数据资产不设功能开关（§4.14）。
- 纯标准库，不新增第三方依赖。

## 5. 风险与回退

- **构建失败保旧快照**：`Rebuild` 校验失败保留旧快照服务并向前端报错（S5），转发不中断。
- **性能回退**：切片 7 benchmark 为硬门槛，不达标回退做加载期按类型/首段分桶（语义不变）并回填 STEP 分析。
- **旧 DSL 兼容破坏**：切片 2/4 的旧格式回归用例为红线，先跑再用。
- **表结构遗漏方言**：三方言脚本由 DATA_DICT 单一来源人工对照生成，切片 1 终验以数据库页表结构检查三方言零差异为准（有条件时 mysql/pg 集成测试环境验证）。
