## §0 断点续传（接手者从这里开始）
1. 读项目状态行与 §1 总表（多项目合表时逐项目判定，某项目完结不阻塞其余「进行中」项目的续传）：
   - 某项目全部步骤「已实施」→ 该项目终验与呈报未做则先做（宪法 §5），改其项目状态「待人类验收」，此后该项目停止一切实施动作（归档删除与新开工均须人类确认）；
   - 某项目状态为「待人类验收/等待人类」→ 该项目不实施任何动作，向用户呈报等待点（待人类验收：终验结论＋已知边界＋临时决策清单；等待人类：受阻原因与所等待的决定）；
2. 定位第一个非「已实施」的步骤；其状态含受阻标注时，读该 STEP 回填区受阻记录，未解除则转向总表中下一个不依赖它的步骤（多项目合表时跨项目同理）；
3. 若为「实施中」，先跑该 STEP 验证节预写的接手核实命令（无副作用、可重复执行）：
   - 通过 = 退出码 0 且确有本步测试被执行（防空跑假绿）→ 已完成部分完好：仍有未勾选项则从首个未勾选项继续，禁止重做；已全勾则补跑本步完整验证，通过即改「已实施」收口；
   - 不通过 → 按该 STEP 回填区锚点清单逐个定位，只补缺口；
   - 仍裁决不了 → 以代码为准，修正文档；
4. 若为「待实施」但锚点检索已有产物命中（中断发生在动作落地后、勾选保存前）→ 先核实产物再续做，禁止从零重写覆盖现场；
5. 每次接手核实后、以及每次状态迁移收口时，跑状态一致性自检（命令模板见宪法 §4.1 附；**Windows Git Bash 适配**：MSYS2 管道会把 `\n` 转 `\r\n`，须对提取串与状态值 `tr -d '\r'` 后再比对，否则误报"文件不存在"）；
6. 严禁凭会话记忆做任何实施判断。

## §2 执行期红线（自仓库法摘录，冲突时以仓库法原文为准）
- 构建/测试/静态检查一律用原生命令行（`go build` / `go test` / `go vet`），禁止调用 make（仅支持 Linux）；前端开发用 `-tags dev` 编译。
- 运行目录红线：程序必须在 `bin/` 目录运行，严禁项目根目录执行（运行时文件跟随工作目录生成）。
- `bin/hotscripts/sql/` 开发期不放任何外挂脚本，发现残留即删（外挂旧脚本会掩盖内嵌更新）。
- 数据字典红线：六表三方言脚本 + `docs/DATA_DICT.md` + Go 枚举三处同步，缺一即违规；公共字段 UTC 惯例与既有表一致。
- WebUI 红线：toast 唯一提示组件（pages.md §4.10）、服务端报错必弹 error toast、数据资产不设功能开关（§4.14）、全局公共区域与页面解耦。
- 前端改动必须开浏览器实看渲染效果并截图留证，禁止仅以 DOM 快照或接口返回代替。
- 文档同步红线：凡配置项、接口、数据结构、页面/文案变更，完成后逐项核对同步清单（README/CONFIGURATION/COMPONENTS/DATA_DICT/pages.md/接口文档）；实施产出的代码注释与正式文档不得引用计划文档（功能产出自包含）。
- git 提交：本次任务【适用】破例授权（用户 2026-09-21 随开工安排明示授予，见宪法 §3.9）——范围：route-dispatch 分支；一个 STEP 验证通过即提交，并推送远程（禁止 force push、禁止改写已推送历史）；授权范围外的分支/远端照常请示。
