# RockSys 管理控制台 · 页面设计

> 产品概述与设计原则见 [README.md](README.md)，交互与视觉规范见 [interaction.md](interaction.md)。

## 4. 页面设计

### 4.1 整体框架

```
┌────────────────────────────────────────────────────────────┐
│ 顶部:  RockSys 控制台   ·  在线 ●  管理地址   ·  主题       │
├─────────┬──────────────────────────────────────────────────┤
│ 侧边栏  │                    页面内容                        │
│ ● 概览   │                                                  │
│ ○ WAF安全                                               │
│ ○ 入网数据                                                  │
│ ▸ 组件   │                                                  │
│   防护 shield / 透传 trace / … / 结果 result                │
│ ▸ 服务   │                                                  │
│   配置服务 config / 注册 registry / 存储 object / 消息 mq │
│ ○ 脚本   │                                                  │
│ ▸ 配置（置底）                                              │
│   全局配置 config / 数据库 database / 系统日志 syslogs       │
└─────────┴──────────────────────────────────────────────────┘
```

- **侧边栏**：图标 + 名称，当前页高亮；「组件 / 服务 / 配置」为可折叠分组，激活项所在分组自动展开；组件与服务条目以「中文 + 英文」命名，点击直达对应详情页；WAF安全 / 入网数据紧跟概览，「配置」分组置底（全局配置 / 数据库 / 系统日志）。
- **顶部公共横栏**：仅全局常驻项——品牌名 + 版本号（与 `rocksys --version` 一致）、网关连通状态（在线 / 不可达）、管理地址、主题切换。刷新 / 自动刷新 / 最近更新不进顶栏：刷新是页面局部能力，由各页面自带的页内按钮承载（概览、WAF安全、全局配置、脚本、日志、文件编辑、组件/服务详情等均各有页内刷新按钮）。**管理地址由全局模块自行获取**（`main.js` 启动时请求 `/admin/config` 取 `admin` 字段注入顶栏，服务未就绪时有限次重试；鉴权部署下启动时该接口为 401，登录成功后由认证视图经 `Rock.main.fetchBaseInfo` 补拉一次），**不依赖任何业务页面供数**——直接进入或刷新非概览页（如 `#/database`）顶栏同样有值。
- **登录**：管理接口绑定非回环地址时，进入控制台前需登录（账号密码），登录成功签发的 JWT 自动携带；回环地址本机免登录。

### 4.2 概览

目标：**30 秒完成巡检**。页面分两个页签：**「总览」**（默认，下述仪表盘内容，行为不变）与**「小黑屋」**（当前在押的封禁预览，含永久封禁）。

```
[页签] 总览 | 小黑屋
┌─ 网关信息（一行横条）────────────────────────────────────────┐
│ 监听端口 :8080   转发地址 http://…            进入全局配置 → │
└───────────────────────────────────────────────────────────┘
┌─ 运行指标（含趋势图）──────────┐  ┌─ 资源监控 ─────────────────┐
│ 每秒请求 延迟50% 延迟95% 延迟99% │  │ CPU      ▓▓▓░░░░ 3.2%     │
│ 错误率 运行时间 211天12:47:40   │  │ 内存     ▓▓▓▓░░░ 19.0%    │
│ · 趋势折线                     │  │ 进程内存 · Goroutines      │
└─────────────────────────────┘  └───────────────────────────┘
┌─ 流量统计 ────────────────────────────────────────────────┐
│ [近24小时|今日|近7天|近30天|自定义]                          │
│ 请求次数 PV UV 独立IP | 拦截 攻击IP | 4xx数/率 4xx拦截/率 5xx数/率 │
│ · 访问情况折线   · 拦截情况折线   · 地理位置 Top 国家（访问/仅拦截）│
└────────────────────────────────────────────────────────────┘
┌─ HTTP 数据流 ─────────────────────────────────────────────┐
│ Client → 入口 → [L1 防护: shield→trace→auth] →             │
│         → [L2 决策: dispatch→rewrite→script] → 转发引擎    │
│         → 后端 → [L3 结果: result→copy→obs] → Client       │
│ （节点=组件，内嵌启停开关+名称，点击名称跳组件页；             │
│   关闭组件灰化虚线，一眼看出链路缺口）                        │
└────────────────────────────────────────────────────────────┘
┌─ 服务状态总览 ────────────────────────────────────────────┐
│ [开关] 配置服务 config · 独立                              │
│ [开关] 注册 registry  · 独立                              │
│ …（4 个）                                                  │
└────────────────────────────────────────────────────────────┘
```

- **网关信息（一行横条卡）**：监听端口、转发地址两项一行排布（管理地址由顶栏全局展示，此处不再重复），最右侧「进入全局配置 →」蓝色链接，点击横条任意位置可进入全局配置页。
- **运行状态卡（METRICS_WINDOW 重排）**：原「运行指标」「资源监控」两卡合并——实时窗口瓦片（**实时请求速率 / 实时错误率**，窗口桶宽可切 1m / 5m / 15m / 1h，纯计数口径零误差；窗口数据重启后从零累计）+ 运行时间 + 每秒请求采样趋势折线图 + 底部**资源信息条**（机器 CPU / 内存占用进度条（≥80% 转警示色）+ 进程内存、Goroutines、核心数；系统级 CPU/内存仅 Linux 可得，其他平台行内降级提示）。观测未开启时显示引导卡片。延迟分位数（P50/P95/P99）不在此卡——已拆分至流量统计区按时间范围精确统计。
- **流量统计延迟瓦片（METRICS_WINDOW）**：延迟 P50 / P95 / P99 / 平均延迟（毫秒）——随所选时间范围对 access_log.total_ms 精确统计（SQL 分位数），范围内无数据显示「—」。
- **流量统计**（页面局部区块，不动顶栏/菜单；排在运行状态卡之前）：时间范围预设 **近 24 小时 / 今日 / 近 7 天 / 近 30 天** + 复用 `dateRange` 自定义（默认近 24 小时，传参换算 UTC）；**九瓦片指标**：请求次数 / PV / UV / 独立 IP、拦截数 / 攻击 IP、4xx 数及率 / 4xx 拦截数及率、5xx 数及率；**地理位置分区**（并入本卡，紧接指标瓦片之下）：世界/中国热力地图 + Top 地区排名，访问 / 仅拦截（blocked）切换；**访问情况 / 拦截情况**双趋势折线（UTC 时间桶，桶宽自适应）+ 峰值标注。数据源 `/admin/obs/traffic/summary` `/series` `/geo` 三端点（契约见 `docs/api/obs.md`）。降级：obs 未开启 → 页内「功能未开启」引导卡（503 豁免 toast）；**DB 数据访问层未就绪的 503（响应文本含「数据访问层」）不属此列**——观测已开但 `DB_DRIVER`/`DB_DSN` 未配置，渲染引导卡会让用户去开观测而问题永远解不了，须按普通错误弹 error toast + 行内说明；obs 未开启时不显示「清空缓存」按钮（避免必然失败的入口）；`SHIELD_EVENT_LOG_ENABLED=false` → 拦截侧瓦片显示「—」；GeoIP 未就绪（`geo_ready=false`）→ 地理位置分区显示**常驻警告引导卡**（说明缺哪个 mmdb 文件、去哪下载、放置后重启生效），并在此类页面会话内首次弹一次警告 toast（sessionStorage 标记防重复）。指标口径详见 `docs/api/obs.md` §3.20（请求次数=访问+拦截趋势各桶之和可对账）。**加载体验**：summary/series/geo 三端点均为查库聚合重操作，前端请求超时放宽至 30 秒（默认 15 秒）；**三区独立加载**——指标卡/地理位置/趋势图各自独立请求、谁先成功谁先显示、各自吃缓存，加载中一律显示统一「数据加载中，请耐心等待」动画提示（首次加载/切换范围/点重试/手动刷新同一呈现；首次加载为占位提示，已有旧数据时在原内容上方叠加**加载浮层**，提示组件为纯 HTML/CSS 结构，同一页面多个容器可同时各自显示）；**请求锁防连点**——任一端点在途（含 30 秒超时窗口）时切换时间范围/重试/清空缓存等操作被拒绝，统一 toast「请求进行中，请耐心等待当前查询完成后再操作」，防止连点发出多条慢 SQL；卡片标题右侧「清空缓存」按钮（POST `/admin/obs/traffic/cache_clear`）清空服务端统计缓存后强制重聚当前范围，刚写入的日志可立即见统计。
- **HTTP 数据流**：按链路顺序展示组件（入口 → L1 防护 → L2 决策 → 转发引擎 → 后端 → L3 结果），**节点内嵌启停开关 + 中文/英文名**，点击名称跳组件详情页；关闭组件灰化虚线（一眼看出链路缺口），状态由开关直接体现。
- **服务状态总览**：4 个独立服务大卡片，**左上 switch 直接启停**（二次确认），点击名称跳服务详情页。
- **「小黑屋」页签**：当前在押的**全部封禁**条目预览（未过期、未软删；永久封禁 `expires_at` 为空，视为不过期一并展示）。表格六列：封禁 IP / 封禁原因（block_type 枚举名）/ 命中次数 / 封禁次数 / 封禁时间（首次）/ 解封时间（永久封禁显示「永久」），限时封禁按解封时间升序（临近解封在前）、永久封禁殿后；client 模式不分页（拉 `limit` 条，默认 20），表格下方展示「共 N 条在押」（超出预览条数提示仅展示前 N 条），**「管理全部黑名单 →」**主色链接固定在卡片标题行右上角，跳黑白名单页（链接可点击性规范见 §4.15）；空态文案「**小黑屋空空如也**」；切到该页签时拉取，并随首页静默重载联动刷新（手动刷新/开关操作触发，「总览」页签行为不变）。数据源 `GET /admin/shield/jail`（契约见 `docs/api/shield.md`）。加载失败统一弹 error 级 toast（不自动消失）并在卡片内保留行内错误提示；仅静默重载失败不弹 toast（防刷屏），只更新行内提示。

### 4.3 组件 / 服务（详情页）

目标：**一组件一页，状态与配置分页签**。

```
面包屑：概览 / 组件 / 防护 shield
┌─ 页面公共区域（面包屑下、页签上方）───────────────────────┐
│ [开关] 防护 shield  [入口环节]             [⟳ 刷新]        │
│ 入口安全防护：按 IP 黑白名单、WAF 规则与限流拦截请求…       │
├────────────────────────────────────────────────────────────┤
│ [状态] [配置(8)]                                            │
├────────────────────────────────────────────────────────────┤
│ 状态页签：                                                  │
│  启用时间 xx · 最近切换 xx · 状态：正常                      │
│  数据流位置：位于数据流「入口环节」…                         │
├────────────────────────────────────────────────────────────┤
│ 配置页签：顶部局部搜索 + 该组件独有配置项（行内编辑，同全局配置风格） │
└────────────────────────────────────────────────────────────┘
```

- **统一页签**：所有组件与服务详情页完全同构——默认「状态」页签，第二个「配置」页签（数量角标）；页签状态写入 URL（`?tab=config`），刷新不丢。
- **页面公共区域**：面包屑下方、页签上方统一承载启停开关 + 中文名/英文名 + 环节标签 + 组件描述，组件/服务页信息一眼可见。
- **状态页签**：运行信息卡片 = 启用时间 + 最近切换 + 状态消息 + 数据流位置示意（开关/名称/环节/描述已上移公共区域，不再重复）。
- **配置页签**：该组件/服务独有配置项（经 `COMPONENT_PREFIX` 过滤，复用配置渲染器）；无独立配置项的组件（如透传 trace、配置服务 config）显示空态引导；脚本组件附"去脚本页发布策略"链接。有配置项时页签内容顶部带**局部搜索**（`components/cfgSearch.js`，风格与交互同全局配置页搜索：KEY/标题/说明综合匹配、命中高亮、↑↓ 选择、Enter/点击定位并自动进入行内编辑），作用域仅限本组件配置项，供 shield 等数十项配置的组件局部检索。
- 启停交互：开启/关闭均二次确认，失败透出具体原因，操作后自动刷新。

### 4.4 全局配置

目标：**全局基础设施配置；组件与服务配置前往各自页面**。

```
├─ 搜索工具栏: 🔍 搜索配置项 KEY / 标题 ───────────────────┤
├─ 分组标签: [网关] [数据访问] [其他] [可信代理] ───────────┤
│ 网关                                                       │
│ 监听端口        8080                 [修改]               │
│ 默认后端        http://…             [修改]   ⚡已即时生效  │
│ …                                                         │
├─ 组件配置（链接卡片）────────────────────────────────────┤
│ 防护 shield · 黑白名单/限流/WAF   [8 项配置]  去配置 →    │
│ 透传 trace  · 链路标识           [无独立配置]  去配置 →   │
│ …（9 个数据流组件）                                       │
├─ 服务配置（链接卡片）────────────────────────────────────┤
│ 注册 registry · 服务注册与发现    [n 项配置]  去配置 →    │
│ …（4 个独立服务）                                         │
└───────────────────────────────────────────────────────────┘
```

- **配置项搜索**（页头与分组页签之间的工具栏，纯前端过滤无新接口）：输入即出下拉结果（防抖 150ms），**综合搜索 KEY / 标题 / 说明(Usage)**，按 KEY 优先排序（KEY 前缀 > KEY 包含 > 标题包含 > 说明包含），命中高亮，说明命中时展示上下文摘录，结果行展示 KEY/标题/归属徽标（分组或组件·服务）/当前值（敏感项掩码）/需重启标签；↑↓ 选择、Enter 定位、Esc 关闭，超 20 条提示细化关键字。**单一编辑路径**：结果点击或回车 = 定位——全局项切换到所属分组页签并滚动高亮闪烁后**自动进入行内编辑**；组件/服务专属项跳转对应详情页配置页签（`?tab=config`）后同样定位入编辑。需重启项仅定位不进入编辑（与行内一致不提供修改入口）。不另设弹窗编辑，避免双编辑路径长期双维护。

- **排列顺序**：真正的全局配置（网关 / 数据访问 / 其他）在前，组件与服务配置入口链接卡片置后，避免遮挡常用全局项。
- **入口链接**：组件与服务各自的配置项已迁至对应详情页的「配置」页签，全局配置以链接卡片引导跳转。
- **保留分组**：仅网关（监听/后端/超时等底座项）、数据访问（DB_）、其他（无归属项）三类全局基础设施配置。
- 每项展示：配置名称、当前值、默认值、中文说明、示例；提供"恢复默认值"。
- **修改**：行内编辑 → 保存 → 提示"⚡ 已即时生效，无需重启"；热更即持久化（写回 `.env`）。
- 敏感项默认掩码；需重启才生效的项（如监听端口）置灰标注。

### 4.5 脚本

目标：**可视化管理策略脚本，发布与回滚**。

```
┌─ 脚本列表 ────────────────┐ ┌─ 编辑器 ───────────────────────────┐
│ 规则A        v3 ● 生效中    │ │ [规则A]  语法校验通过   [发布] [回滚] │
│ 规则B        v1 ● 生效中    │ │ ┌───────────────────────────────┐ │
│ (空)         -  ○ 未发布    │ │ │ -- 策略脚本                     │ │
│ [新建脚本]                  │ │ │ 当 访问路径 = "/拦截" 时        │ │
└───────────────────────────┘ │ │   返回 禁止访问                 │ │
  ▲ 版本时间线（点击回滚）     │ │ 结束                            │ │
  v3 ── 今天 10:12           │ └───────────────────────────────┘ │
  v2 ── 今天 09:40  ← 回滚到 │ [提示: 脚本只做策略控制，不改业务数据]  │
  v1 ── 昨天 18:00           └──────────────────────────────────────┘
```

交互流程：

1. 左侧脚本列表（名称 + 当前版本 + 生效状态）；支持新建命名脚本。
2. 编辑器支持脚本语法高亮与基础校验；顶部提示脚本只做策略控制。
3. **发布**：校验通过后发布 → 版本号 +1 → 列表刷新，提示"已发布 v3"。
4. **回滚**：在版本时间线选择目标版本 → 二次确认 → 生效版本回退；选择"移除"可将脚本下线。
5. 发布失败（语法不合法 / 含被禁能力）→ 明确提示原因，优先展示出错位置。

> **注意**：脚本保存在网关运行内存中，网关重启后需重新发布。回滚可选历史版本（仅限本次运行期内发布的版本）。

### 4.6 入网数据（原访问日志）

目标：**按时间范围与路径查看 HTTP 入网请求日志，定位单个请求**（与系统日志分开）。

```
┌─ 存储占用 ──────────────────────────────────────────────┐
│ 存储占用：日志库占用 16.3 MB │
├─ 查询条件 ───────────────────────────────────────────────┤
│ 开始 [日期][时间]  结束 [日期][时间]  [查询]  [导出下载]   │
│ 路径精确 [/api/order/1]  路径模糊 [/api/order]  [重置]    │
│ 状态码 [全部▾]  耗时排序 [时间▾]  只看异常 [□]            │
├───────────────────────────────────────────────────────────┤
│ 时间          方法  路径            状态   耗时         │
│ 2026-08-05    GET   /api/order/1    200    12ms         │
│ …                                                       │
│ 共 1,234 条 · 每页 [20▾]      ‹ 上一页 第 [5]/62 页 下一页 › │
└───────────────────────────────────────────────────────────┘
│ 点击行打开详情弹层：请求来源、分环节耗时、转发目标、流量大小 │
```

- 按时间范围查询（日期 + 时间组合，精确到分；默认当天全天），支持导出下载。
- 支持路径精确 / 模糊过滤（后端查询）、状态码筛选、耗时排序（总耗时/出网耗时升降序）、只看异常（状态分组/仅异常/耗时排序均由后端执行，配合服务端分页）。

### 4.10 提示消息规范（toast 唯一组件）

全站提示统一经 `Rock.ui.toast(message, type, duration)`（`webui/assets/js/ui.js`），按类型分级：

| 类型 | 场景 | 行为 |
|------|------|------|
| `success` / `info` | 操作正常反馈（保存成功、已导出等） | 显示完自动消失（默认 3.2s），点击可提前关闭 |
| `error` / `warning` | 异常信息（操作失败、校验不通过等） | **不自动消失**：需点右上角 ✕ 或「知道了」按钮关闭；传显式 `duration` 时仍自动消失（如登录页警告 6s） |

- **服务端报错必须弹统一 error toast（强制）**：后端接口返回失败（非 2xx 或 `ok:false`）时，必须经 `Rock.ui.toast(msg, 'error')` 弹统一报错组件（不自动消失）；页内表格/卡片正文可**同时**保留灰色行内错误兜底，但**只写行内灰字、不弹 toast 视为违例**。仅两类豁免：① 程序化静默刷新（`opts.silent`，如保存/操作成功后的后台重拉）失败不弹（防刷屏），但行内提示必须更新；② "功能未开启"降级引导态（观测未开启、DB 未配置等 503/404，页内已有引导卡片）不弹——引导卡片必须与根因匹配，例如 obs 数据访问层未就绪属"DB 配置缺失"而非"功能未开启"，引导去开观测是错误出路，应按普通错误提示。实现约定：各视图 load 类函数的失败分支统一用 `!opts.silent && e.status !== 0` 判定是否弹 toast；其中 `status === 0` 仅表示**网络不可达**（连接失败/DNS 解析失败，由顶栏常驻横幅承载），**请求超时用独立状态 `408`**（超时不算不可达，不得触发横幅），因而同样落入 `status !== 0` 分支正常弹 toast；`main.js pageLoaders` 的 fetch 必须把 `refreshPage` 传入的 opts 透传给视图（不得写死 `load({})` 丢弃 `silent`）。SSE 流式连接（系统日志实时流）的断连/重连属持续状态而非单次请求，用页内状态指示、不弹 toast（避免重连风暴）。
- **切换页面自动清空**：路由切换时 `main.js` 调 `Rock.ui.clearToasts()`，常驻提示不跨页残留；刷新页面天然清空。
- **文案原则**：异常提示必须说清"**发生了什么 + 为什么 + 下一步怎么办**"。后端返回的错误文案同样遵守（如 IP 加黑撞软删/过期记录时，须点破"记录存在但未生效"并指引到黑名单列表恢复，而不是只说"已存在"）。
- **非标准错误响应兜底**（`api.js` 统一处理，各页面无需关心）：错误文案决策链为 ① JSON 的 `error`/`message` 字段 → ② JSON 但缺字段 =「服务端响应格式异常（HTTP xxx）」→ ③ 短纯文本（≤200 字符且不含 `<`）原样展示 → ④ HTML 错误页/超长文本/不可读 body =「服务端响应异常（HTTP xxx），请查看服务端日志」。HTML 与超长文本一律不灌入提示条。
- **统一加载指示条**（`api.js` 统一实现，中性态、非 toast）：每个经 `Rock.api.*` 发起的请求在顶部显示细进度条 + 文案，请求结束（成功/失败/超时）自动隐藏，成功/失败提示仍由调用方经 toast 触发。默认文案「数据请求中…」，调用方按第三参覆写语义文案：`api.get(url, timeoutMs, loadingText)` / `api.post(url, timeoutMs, loadingText)(body)` / `api.textMeta(url, timeoutMs, loadingText)`（如 logs 页传「日志数据加载中…」）。并行请求计数，全部结束才隐藏。
- 调用方不得自行实现弹层提示；确需更重的确认场景走 `confirmDialog`（等价取消语义，ESC 可关）。

### 4.11 数据库（服务 → 数据库 · 表同步 / 表概览 / 表数据 / SQL历史页签）

目标：**存量数据库表结构演进的产品化**——无需命令行，图形化完成"检查差异 → 编辑 SQL → 执行 → 复核"闭环。菜单入「服务」分组子项「数据库」，页内 `tabs` 页签（按使用频率排序）：「表同步」（结构比对与同步，原"表结构"）+「表概览」（空间占用，原"数据表概览"）+「表数据」（外部数据源、表结构对齐、数据迁移、GeoIP 数据同步）+「SQL历史」（审计追溯，原"执行历史"）。页签上方有**公共状态区**常驻展示数据库占用总空间、业务表数量与当前方言（与全局配置页搜索栏同层级的公共数据状态）。空间占用为**按需懒加载**：表清单/精确条数/库级总占用由 `GET /admin/db/size` 毫秒级返回（条数走覆盖索引 `COUNT(*)`，百万行约数十毫秒；总量 SQLite 取 `page_count×page_size`）；占用空间按「数据 + 索引」两列拆分（SQLite 表 B-tree 含溢出页 / 各索引 B-tree；MySQL 聚簇索引与二级索引；PG 表堆与索引）；**逐表占用在 SQLite 下按需点「计算」触发**（`GET /admin/db/table_size?table=`，需遍历全库页树，大库首次秒级~数十秒，结果服务端缓存 10 分钟），MySQL/PG 由系统表直接给出无需点算。未加载时状态区显示"未加载 + 加载"、表概览显示"尚未加载"引导卡（**不显示"库中无表"**）；加载中显示统一加载提示；失败时状态区显示"加载失败 + 重试"、表内显示错误卡 + 用户主动触发失败弹统一 error toast——状态严格区分，避免把"未加载"误报成"库里没有表"。

```
面包屑：服务 / 数据库
┌─ 说明区 ──────────────────────────────────────────────────┐
│ 期望结构 = 当前运行 SQL 源（外挂 HOT_SCRIPTS_DIR/sql/ 优先、 │
│ 内嵌兜底）；实际结构 = 当前数据连接 catalog                 │
│ 检查只读不写；「执行SQL」直接作用于当前数据库，DDL 不可回滚， │
│ 执行前建议先备份                                            │
├─ 操作区 ──────────────────────────────────────────────────┤
│ [表结构检查]  [执行SQL]（危险色，编辑器有内容才可点）        │
│ [ ] 后台执行（长语句走任务中心，摆脱请求超时）              │
├─ 差异结果表 ──────────────────────────────────────────────┤
│ 表 / 对象 / 差异类型 / 期望 / 实际 / 建议                   │
│ B 缺普通列 [自动]  warn_times  INTEGER…  （空） 缺普通列…   │
│ C 缺 PK…  [需人工]  …                                     │
├─ SQL 编辑器（codeEditor，sql 高亮）────────────────────────┤
│ -- ip_blacklist · 缺普通列 warn_times                      │
│ ALTER TABLE ip_blacklist ADD COLUMN warn_times …;          │
└───────────────────────────────────────────────────────────┘
```

交互闭环：

1. **检查**（主按钮）：调用 `GET /admin/db/schema`，只读不写。
   - 无差异：成功 toast（自动消失）+ 空态"数据库结构与当前 SQL 源一致"。
   - 有差异：差异结果表 + 编辑器预填自动项生成的 SQL，toast 汇总"发现 N 处差异（可自动处理 M 处）"。
2. **分级展示**：差异按 A-F 分级着色——自动项（缺表/缺普通列/缺索引/E 级类型与非空与默认值不一致[仅 mysql/pg 目标]）绿、需人工橙、仅提示灰；每行展示期望 vs 实际与建议文案，需人工/仅提示项给出原因（如 SQLite 不可 ADD 带约束列与改列、不生成 DROP）。
3. **编辑**：编辑器预填的 SQL 可自由编辑（含手工补写需人工项的救急语句），支持复制到剪贴板；「执行SQL」按钮编辑器有内容才可点。
4. **执行**（危险按钮）：`confirmDialog` **danger 强确认**——说明将执行 N 条语句直接作用于当前数据库、DDL 不可回滚、建议先备份；确认后调用 `POST /admin/db/exec`。提交后到响应返回期间按钮保持禁用（文案「执行中…」），**danger DDL 禁止并发二次下发**。
5. **逐条结果**：表格展示每条语句的执行结果（成功含受影响行数、失败标红）；部分失败时**常驻 toast**（错误级，不自动消失，文案三要素：第 N 条失败 + 原因 + 前面已生效不可回滚、修正后仅重发剩余语句）；全部成功为汇总 toast（自动消失）。
6. **复核闭环**：无论成败，文案均引导"再次点击「表结构检查」复核差异已消除"，形成 检查 → 执行 → 复核 闭环。

**SQL历史页签**：`sql_exec_log` 审计记录分页展示（每条语句一行，服务端分页每页 20 条）——
执行时间、批次（前 8 位 + 批内序号）、语句原文（悬停看全文）、结果（成功/失败标签，失败行标红）、
受影响行数、耗时、来源 IP、失败原因（悬停看全文）。**点击任意行弹出详情弹层**（复用 `detailModal`）：
完整语句原文（等宽块展示 + 一键复制）与执行快照全量字段（时间、批次/序号、结果、影响行数、耗时、
来源 IP、执行渠道、失败原因），语句长不再受列表截断限制，满足逐条审查。永久保留，刷新/换会话均可追溯，
补齐"谁在何时执行了什么"的审计能力。执行 SQL 后自动失效缓存，切回页签即见最新留痕。
**加载失败与空态严格区分**：拉取失败渲染错误卡 + 「重试」出口并说明"这不代表没有执行记录"，不得渲染成
「暂无执行记录」（审计场景误导）；已有旧页数据时展示旧数据并标注"本次刷新失败"。

**表概览页签**：库内全部业务表的占用统计——表名、表备注、数据条数、占用空间（含占库内总空间的占比条）。
条数为精确值（对每张表动态 `COUNT(*)`，不取系统表估算列）；占用空间为数据+索引合计，取自方言系统表
（MySQL `information_schema`、PG `pg_total_relation_size`；SQLite 走 dbstat 按页聚合，总空间取
`page_count×page_size`，dbstat 不可用时逐表空间显示"—"仅总空间保真）。逐表「计算」全局串行：
任一行计算中时全部「计算」按钮一并禁用（行内显示「计算中…」），避免点击被静默忽略。

**表数据页签**：按迁移流程自上而下四张卡——**数据源**（列表含连接名/驱动/脱敏 DSN 与删除；添加表单含连接名、驱动下拉三方言、DSN 输入与「连通测试」按钮，测试不落盘；持久化于 `<CONF_DIR>/dsn.json`）、**表结构对齐**（选目标数据源 → 「检查差异」出差异与 DDL 预览 → 「执行对齐」强确认后逐条执行，遇错停、已存在对象幂等跳过）、**数据迁移**（源默认「本机运行库」、目标仅外部数据源不含运行库、表清单多选、批次输入框默认 1000 并注明性能语义与自动切分、冲突策略清空重灌/跳过冲突 → 「启动迁移」→ 表级进度区：每表状态与行数进度，待迁移表可单表移除，另设整任务取消）、**GeoIP 数据同步**（原挂「表概览」页签，现归位本页签并更名；执行方式为后台任务）。
数据迁移表清单取自「表概览」已加载的业务表；未加载时卡内提示先到表概览加载。单表失败不阻塞后续表（进度区逐行显示失败原因），目标=运行库被服务端拒绝并提示，并发互斥为**规则式**（内存态规则在「后台任务」页原样展示）：迁移/结构对齐执行/GeoIP 同步/SQL 后台执行的来源标签（CreatedBy）同入互斥公共集——集内至多 1 个任务在跑，命中规则被拒时弹常驻 error toast 并附冲突任务 ID 与标题；未入集的来源（未来新增长任务）默认并行不互斥。GeoIP 同步无时间预算（后台任务默认无超时，跑多久由数据量决定），取消在块/批边界收工；GEOIP_SYNC_INTERVAL 驱动的定时同步同为任务中心实例，同集被占时该轮跳过（定时任务页记「跳过」，下轮到点续接）。

**后台任务交互（共用组件）**：数据迁移、表结构对齐执行、GeoIP 数据同步、SQL 后台执行四处共用「提交 → 轮询 → 进度/结果展示」交互——提交后立即拿到任务 ID（不再受 15 秒 HTTP 超时压制），组件每秒轮询任务详情渲染进度与结果；**页面恢复**：各卡加载时查询任务列表，存在本卡来源且运行中的任务即自动恢复进度区并续上轮询（任务 ID 不落前端存储），切页签/刷新页面不丢失进行中任务的进度。

> 数据访问层未配置或表清单未装配时页面提示不可用及原因。提示统一走 `Rock.ui.toast`（§4.10 提示分级：检查/执行成功自动消失、失败常驻），确认走唯一 `confirmDialog`。后端契约见 `docs/api/database.md`。

### 4.12 WAF安全 · 黑白名单与封禁（IP 黑名单增强）

目标：黑名单条目来源语义化（block_type 0=其他 / 11=人工收录）、从文件同步入库、行内/详情就地封禁、列表排序与封禁次数可视、自动拉黑可配置可观测。

**黑白名单页签（列表）**：

**实时拦截卡（桶宽切换与落库总数）**：

- **窗口桶宽 chips**：实时计数瓦片支持 `1m / 5m / 15m / 1h` 四档桶宽切换（`GET /admin/shield/metrics?window=`，缺省 1m；服务端由内存 1 小时窗口 = 60×1 分钟桶整点聚合，零误差）；切换即拉。
- **「本次运行落库（重启清零）」标签**：原「累计落库」语义消歧——`written`/`dropped` 是**本次运行**累计（进程重启清零），标签与 tooltip 说明此语义。
- **「落库总数」瓦片**：新增，取 `GET /admin/shield/total` 查库全范围总数（**受保留期影响**，清理会减少；与内存窗口口径不同）；进页查一次，不跟随窗口/桶宽刷新。

- **Top 攻击源 IP 表新增「地区」列**：数据源 stats `top_ips` 行的 `country`/`country_name`/`city`（geo 查询时解析，未随 GEOIP_LIST 方案改动）；GeoIP 未加载时服务端不下发该字段，前端显示占位「—」并复用 geo 缺失引导（见 §4.2 流量统计）。

**自动拉黑说明**（WAF 页说明文案与配置页呼应）：后台风控引擎按配置窗口统计各 IP 拦截次数（**排除 block_type=1 黑名单自我拦截**，避免封禁惩罚自我生产续封证据），**按风险分档**自动写入黑名单——仅精确 IP，拉黑原因取该 IP 达标档内次数最多的类别；软删/过期条目被再次命中自动恢复且解封时间延长为默认 TTL ×10。分档策略：**攻击档**（风险路径/路径遍历/SQL注入/XSS）窗口内命中 1 次直接永久封禁（策略定死代码不可配）；**爬虫档**（爬虫/扫描器 UA）达爬虫阈值限时封禁；**通用档**（限流/方法白名单/体积超限/规则 deny）达通用阈值限时封禁；多档达标取最严档。限时封禁累计入狱达 `SHIELD_AUTO_BAN_REPEAT_LIMIT`（默认 5，0=永不自动转永久）转永久。配置项：`SHIELD_AUTO_BAN_ENABLED`（默认 true，★ 随 `SHIELD_ENABLED` 热联动：防护关闭时引擎空转不生效）/ `SHIELD_AUTO_BAN_THRESHOLD`（默认 50）/ `SHIELD_AUTO_BAN_CRAWLER_THRESHOLD`（默认 20）/ `SHIELD_AUTO_BAN_REPEAT_LIMIT`（默认 5）/ `SHIELD_AUTO_BAN_WINDOW`（默认 10m）/ `SHIELD_AUTO_BAN_TTL`（默认 24h，0=永久），全部每轮读配置支持热更（详见 `docs/CONFIGURATION.md`）。

### 4.13 WAF安全 · UA黑名单/UA白名单（规则文件行级管理）

「黑白名单」页签为四个子页签：IP黑名单 / IP白名单（DB 表 CRUD，见 §4.12）/ **UA黑名单** / **UA白名单**（规则文件行级管理，视图 `views/ualist.js`）：

- **数据模型**：无 DB 表、无新增配置项——数据源即 WAF 规则文件 `rules/crawler_ua.txt`（UA黑名单）与 `rules/ua_whitelist.txt`（UA白名单），读写走规则三端点（`GET /admin/shield/rules/file` / `POST /admin/shield/rules/save`），保存原子写落 `HOT_SCRIPTS_DIR/rules/`，ScriptHub ≤3s 自动热更生效。
- **语义**：UA黑名单开关即 `SHIELD_WAF_CRAWLER_UA`（默认 false，开启需重启）；UA白名单无开关、有数据即生效（同 IP 白名单），命中者在黑名单判定前放行、**仅豁免爬虫 UA 拦截一步**——SQL/XSS/风险路径/限流/IP 黑白名单等其余检测照常（搜索引擎爬虫带攻击特征照样拦）；空 UA 不命中任何白名单模式、照拦。
- **行级管理**：生效模式表格（小写子串匹配，注释行不参与匹配、原样保留）+ 单条删除（确认弹层，仅移除模式行）+ 追加（输入转小写、空值/`#` 开头/重复模式拦截、请求中禁用输入防双击）+ 恢复默认（整体回退编译期内嵌内容，确认弹层 danger 级）；保存成功后乐观渲染，3.5s（热更窗口后）后台重拉对账。
- **入口分工**：本页做行级管理；改注释/排序等**整文编辑**前往「文件编辑」页签（crawler_ua.txt / ua_whitelist.txt 仍在该页签清单内，两处粒度不同、不冲突）。
- **加载失败**：统一弹 error toast（503 引导态除外），页内保留行内错误兜底。

### 4.14 体验规范 · 开关设置原则

开关不是越少越好、也不是越多越好，以**用户体验与流程设计的具体场景**为准：能替用户减负、按需取舍攻击面/行为边界的开关保留（如 shield 各检测项独立开关）；纯技术便利、或给数据类资产配的开关不设——**有数据即生效**（如 UA白名单与 IP 白名单同例，数据本身就是开关）。把"配置当数据收录"或"为对称而对称"加开关，均属违例。

### 4.15 跳转链接与可点击性规范（2026-09 全文审查沉淀）

**问题背景**：小黑屋「管理全部黑名单 →」曾以灰色（form-hint 灰字）内联呈现，用户无法识别可点击，体验差。全文审查后沉淀如下规范：

1. **可跳转文本一律主色**：正文中可点击跳转的链接（含 `form-hint` / `card-sub` / `card-title` 说明文字内的链接）必须使用主色（`var(--primary-light)`）+ pointer 光标，**禁止灰色文字充当链接**。全局样式已覆盖（`style.css` §27），页面写裸 `<a>` 即自动生效；独立链接用 `.link-like` 类。
2. **可点击卡片必须 pointer**：整卡可点击的（`.card.hoverable`、数据流节点 `.df-node`）cursor 必须为 pointer；不可点击的节点（`.df-ext` / `.df-base`）显式 `cursor: default` 区分。
3. **跳转出口位置**：数据卡片的管理/跳转出口固定放**卡片标题行右上角**（`card-title` 为 flex space-between，右侧自然悬挂），计数行只保留数据事实（如「共 N 条在押」），不混入跳转动作。
4. **审查结论（2026-09）**：修正 ① 概览·小黑屋「管理全部黑名单 →」（灰字 → 右上角主色链接）；② UA黑/白名单「前往文件编辑」（灰字 → 主色）；③ 概览服务卡片与数据流节点缺 pointer 光标。其余跳转入口（面包屑 `.breadcrumb a`、全局配置入口卡片 `.cfg-link`、日志行 `.log-row`）此前已符合规范。

### 4.16 定时任务（服务 → 配置 · schedule 只读页）

目标：**系统定时任务统一可见性**（GEOIP_LIST 方案 D15/D18）——有哪些任务、关联开关、上次执行状态，一处看全；**只读登记，不驱动任何任务**（各任务仍由各自触发循环执行）。

- 数据源：`GET /admin/schedule/list`；表列：任务（中文名+name）/ 计划 / 类型（可配型·系统级只读）/ 关联开关（easyconf 配置名 + 实时启用态）/ **最近执行时间**（执行结束时刻）/ **最近执行结果**（成功 / 失败 / 跳过 / 部分完成 / 未登记）/ 说明。本表是**任务定义（工厂）的登记面**，只记「上一轮调度执行的结果」，任务实例的运行时状态只在「后台任务」页查询。结果域词汇：分趟同步的上限先到属设计内节奏，记成功；人工取消执行实例导致本轮未跑完，记「部分完成」（避免把「没跑完」谎报成「已完成」或「已失败」）；真错误记失败；定时轮到点但互斥集被占未执行，记「跳过」。
- 「最近执行时间」仅对纳入状态回写的任务（当前为 GeoIP 关联表同步）有值，其余行显示「未登记（本类任务不在本期状态回写范围）」——防止被误读为「从未执行」；跳过不是执行，故跳过登记不改动最近执行时间。
- 页面无任何写操作（无开关、无触发按钮）；可配型任务的启停经其关联配置项（全局配置页），GeoIP 手动同步在数据库页同步卡与概览地理位置卡。

### 4.17 后台任务（服务 → 配置 · 任务中心观测页）

目标：**长任务实例的统一观测面**——数据迁移、GeoIP 数据同步、表结构对齐、SQL 后台执行等后台任务提交后在「配置 → 后台任务」页集中查看进度、结果与耗时；冲突管控配置原样透出，由用户手动管理（等待/取消）。

- 数据源：`GET /admin/tasks`（含 running 与保留期内终态，终态仅留最近 500 条，服务重启即清空）；表列：标题 / 来源 / 状态（运行中·已完成·失败·已取消，支持下拉筛选）/ 进度 / 结果与耗时（仅失败行显示错误详情，成功/取消行只显示耗时——创建→结束自动计时）/ 创建时间 / 结束时间 / 操作；列表对终态任务不下发进度明细、且默认只返回最近 20 条终态（?limit=N 自定义，0=全量，运行中不受限，has_more 提示截断），详情弹窗经单查补全。
- **并发管控卡**（内存态配置只读展示）：互斥键字段（默认 CreatedBy）、互斥公共集（集内标签至多 1 个任务在跑）、指定互斥集（点对点双向互斥）、来源白名单（未注册来源拒绝提交）。提交任务即时比对规则，命中即拒并提示冲突任务 ID 与标题；未命中规则的任务并行不设限。
- **来源筛选**下拉：选项即白名单（管控配置与筛选器同源，防未注册来源混入的语义一致）。
- **取消**：运行中任务行内「取消」按钮，确认弹窗（危险色）后经统一取消端点送达；任务在当前批次/语句边界收工，已完成部分保留（幂等可续跑）。
- **自动刷新**：存在运行中任务时每 2 秒静默轮询，全部终态后自动停止（不无限刷）；手动刷新按钮常驻。
