# RockSys 磐石系统 · 演进路线图

## 定位

RockSys 磐石系统是一个开源的流量网关：部署在业务系统与外部访问之间，统一承接安全防护、访问控制与流量调度。

名字里的"磐石"是我们对自身角色的界定——**业务系统向前迭代，磐石在后面保持稳定**。上游服务可以扩容、重启、发布，入口这一层始终可靠、行为可预期。底层引擎由团队自研掌控，不仰赖第三方框架。

## 要解决的问题

企业对外提供服务的入口层，长期面临三个矛盾：

1. **安全与可用难两全**：防护规则越严，误拦截越多；放开限制，攻击又挡不住。多数产品只能二选一。
2. **组件多、运维重**：入口能力分散在多个系统里，部署链长、故障面大，中小团队难以维护。
3. **能力与规模错配**：商业网关按大企业设计，价格与复杂度都超出多数团队的实际需要；开源方案又往往缺少产品化的管理界面与持续维护。

磐石系统的取舍是：**核心只做一件事——把每一次访问安全、准确、稳定地送达**。防护、调度、审计等能力全部以可插拔组件的形式存在，用则开启，不用则关闭，互不影响。这让单个组件可以独立演进，也让整体复杂度始终可控。

## 已交付的能力

经过多轮生产验证，磐石系统已经形成从接入、防护到调度的完整闭环：

- **稳定底座**
  - 单文件部署，跨三平台发布，核心转发链长期稳定运行；
  - 防护、规则、可信网络等配置文件支持自动热更新，调整策略无需停机。
- **可视化管控**
  - 内置管理控制台，流量、事件、配置一屏可查，无需手工维护配置文件；
  - 异常提示均给出原因与处置建议。
- **安全防护闭环**
  - 攻击识别（Web 攻击特征、恶意爬虫识别）、IP 黑白名单、路径与 UA 访问控制；
  - 按来源限流、自动封禁与黑名单机制；防护事件全程留痕、可审计；
  - 防护体系部分失效时自动降级到剩余防护手段并实时告警，可用性优先、绝不无声失效。
- **智能流量调度**
  - 平滑加权轮询、一致性哈希（会话保持）、主备节点容灾多种调度策略；
  - 主动健康检查持续探测后端，故障节点自动摘除与恢复，多后端之间流量自动分配。
- **数据层兼容**
  - 支持 SQLite / MySQL / PostgreSQL 三种数据库，企业可复用现有基础设施；
  - 支持脚本扩展，业务逻辑可在入口层安全落地。

### 第一阶段：可靠

把"入口不成为瓶颈"做到极致，工作集中在防护与调度两条线上：

- **请求体安全检测**：当前的攻击识别覆盖 URL、查询串与请求头，请求体（POST 内容）尚未深度扫描——本期纳入，注入类攻击的最后一块盲区就此补齐；
- **精细化限流**：限流已按来源 IP 生效，将扩展到按接口、按访客分级设定门槛，重要业务多留余量，次要流量主动排队；
- **过载保护**：流量超出承载能力时，入口主动、有序地消化压力——拒绝新客、照常服务老客，而不是所有人一起被拖垮；
- **部件忙闲可见**：每个部件的负载状态在控制台亮出来，压力在哪里、离极限还有多远，一眼可查。

这一阶段完成后，入口层在高并发与攻击场景下不再依赖人工干预。

### 第二阶段：智能

在已有的健康检查与故障摘除之上，调度与观测再上一个台阶：

- **熔断**：持续异常的后端在拖累业务之前即被隔离，请求毫秒级换到健康节点，不再傻等超时；
- **自动试探恢复**：修好的节点自动重新上线，全程无人介入；
- **多线路分担**：多线路、多机房场景下，流量按实时状态自动挑最好的路，单条线路故障对访客近乎无感；
- **组件级性能指标**：耗时与错误率精确到组件粒度，系统可以直接回答"哪个组件正在拖慢整体"。

这一步达成时：业务系统获得的整体可用性，机器会坏，但服务不断。

### 第三阶段：生态

当磐石守住了足够多的入口，它本身就成为一片可以生长的土壤：

- **组件生态**：向第三方开发者开放组件规范，社区可以像做应用一样为磐石扩展能力，安全策略、调度算法、行业定制都可以成为独立组件，互相组合、彼此共享；
- **托管服务**：提供一键开通、免运维的云端版本，没有技术团队的企业也能用上企业级入口，版本升级、容量伸缩、故障处置全部托管；
- **AI 流量治理**：AI 代理与 AI 爬虫正在改变互联网的访问模式——谁来识别它们、放行它们、为它们设定规则？磐石站在流量入口，天然是这个问题的回答者。识别 AI 流量、按策略放行与管控，磐石会是企业迎接 AI 时代的第一站。

本阶段为方向性规划，具体节奏将依据社区与客户反馈确定。

## 优势和特色

- **自研底座**：底层引擎自研掌控，性能与稳定性不依赖第三方框架。
- **隔离式架构**：核心转发与增强功能彻底隔离，任何增强组件的故障不影响转发本身。
- **透明**：代码开源，发布记录与更新日志公开可查。
