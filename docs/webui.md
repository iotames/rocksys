# RockSys 管理控制台 产品设计方案

> 面向**平台运维与管理员**的 Web 控制台。本文档描述控制台的功能、页面与交互设计，不含任何技术实现细节。

---

## 1. 产品概述

### 1.1 产品定位

RockSys 磐石是"**永不宕机的反向代理**"，其能力由多个可热开关的组件（挂件）组成。本控制台是 RockSys 的**图形化管理入口**，让管理员在浏览器中完成日常全部运维操作：

- 全部**数据流组件**（9 个：防护 / 透传 / 认证 / 分发 / 改写 / 脚本 / 观测 / 抄送 / 结果）与**独立服务**（4 个：配置服务 / 注册 / 存储 / 消息，消息组件按配置条件装配）的**开启 / 关闭**与状态监控
- 网关与全局基础设施的**配置修改**（即时生效，无需重启）；各组件/服务配置在各自页面
- 策略脚本的**发布与回滚**
- 网关**运行指标**（概览页）与**入网数据 / 系统日志 / WAF安全防护**的查看

核心产品理念贯穿所有页面：**"关闭只是降级，转发永不中断"**。

### 1.2 目标用户

| 角色 | 使用场景 | 关键诉求 |
|------|----------|----------|
| 平台运维 / 管理员 | 日常巡检、故障定位、安全加固 | 一眼看清系统是否正常；快速启停组件；查日志、看指标 |
| 平台研发 | 配置路由 / 防护 / 改写，发布策略脚本 | 可视化配置、脚本版本管理 |
| 交付实施人员 | 现场部署调优 | 免命令行，图形化交付，降低上手成本 |

### 1.3 设计目标

1. **全覆盖**：RockSys 的全部管理能力在控制台中均有入口（见 §6 功能覆盖清单）。
2. **一目了然**：打开首页即知系统是否健康，5 秒内完成巡检。
3. **操作有护栏**：一切影响全局的操作必须二次确认，成功或失败都有明确反馈。
4. **中文界面**：全部界面为简体中文，术语与产品文档一致。

### 1.4 非目标

- 不面向业务终端用户（业务系统有各自界面）。
- 不做多台网关的统一集群管理（本控制台管理单台网关）。
- 不承担业务数据管理。

### 1.5 实现技术形态

| 项 | 说明 |
|----|------|
| 界面风格 | **ElementUI 风格**（中后台经典样式，观感与 ElementUI 组件一致） |
| 实现方式 | 纯静态单页：HTML + CSS + 原生 JavaScript，**不引入 Vue 等前端框架**、无构建链 |
| 交互还原 | 内置 ElementUI 主题样式（静态资源），按钮 / 表格 / 弹窗 / 开关等交互由原生 JS 实现，视觉与交互贴近 ElementUI |
| 交付形态 | 双模式：**生产**全部静态资源内嵌进 rocksys 单二进制（`go:embed`），随网关一起分发，不额外部署、不依赖外网；**开发**（`-tags dev` 编译）实时读 `webui/` 源码目录，改前端文件后刷新浏览器即见、免重新编译 |
| 界面入口 | 网关管理地址（如 `127.0.0.1:19527`），浏览器直接打开控制台 |
| 请求方式 | 控制台只调用网关自身的管理接口（同源），不访问任何第三方服务 |

> 产品设计角度：无论底层如何实现，用户看到的都是"打开一个网址即得控制台"。技术形态只影响交付与部署，不影响本设计中的任何页面与交互。

## 2. 设计原则

| 原则 | 含义 | 落地 |
|------|------|------|
| **转发第一** | 网关是否在线是最高优先级信息 | 首页顶部常驻网关状态与数据流展示 |
| **开关即能力** | 组件以"开关"为第一视角，配置为第二视角 | 组件页 = 状态/配置双页签，首页卡片开关直启 |
| **改配即生效** | 配置保存后即时生效，不重启 | 保存后明确提示"已即时生效" |
| **失败可解释** | 操作失败必须说明原因 | 失败提示展示具体错误原因 |
| **贴近用户** | 界面只讲功能，不讲技术 | 页面用中文功能语言，不出现技术术语 |
| **ElementUI 风格** | 界面统一采用 ElementUI 视觉风格，中后台观感一致 | 全部界面遵循 ElementUI 风格规范（样式与组件观感），不引入前端框架 |

## 3. 信息架构与导航

```
RockSys 控制台
├── 概览            ← 默认落地页（网关信息 · 运行指标与趋势 · HTTP 数据流图 · 组件/服务状态总览）
├── WAF安全防护     ← 安全巡检：拦截统计 / 黑白名单管理
├── 入网数据        ← 流量巡检：HTTP 入网请求日志
├── 组件
│   ├── 防护 shield / 透传 trace / 认证 auth / 分发 dispatch
│   ├── 改写 rewrite / 脚本 script / 观测 obs / 抄送 copy / 结果 result
├── 服务
│   ├── 配置服务 config / 注册 registry / 存储 object / 消息 mq
├── 脚本             策略脚本发布 / 回滚
├── 全局配置         网关 / 数据访问 / 其他；组件与服务的配置入口链接
└── 系统日志         ← 排障入口：系统进程实时日志
```

导航采用**左侧固定侧边栏**，顶部为全局工具条。「组件 / 服务」为可折叠分组；组件与服务每个条目对应一个独立页面（中文 + 英文命名），分组内激活项所在分组自动展开。WAF安全防护 / 入网数据 / 系统日志为顶级菜单（原「观测」分组已提升，URL 不变）。

各页面定位：

| 页面 | 用户任务 | 信息量 | 使用频率 |
|------|----------|--------|----------|
| 概览 | 巡检：系统是否正常，链路各环节状态 | 高 | 每次打开 |
| 组件 | 启停与配置数据流各环节能力 | 中 | 中 |
| 服务 | 启停与配置独立支撑服务 | 中 | 中 |
| 脚本 | 发布 / 回滚策略 | 中 | 低 |
| WAF安全防护 | 安全告警与拦截追溯 | 中 | 中 |
| 入网数据 / 系统日志 | 排查单个请求 / 进程问题 | 高 | 中 |
| 全局配置 | 调整全局基础设施参数 | 高 | 低 |

## 4. 页面设计

### 4.1 整体框架

```
┌────────────────────────────────────────────────────────────┐
│ 顶部:  RockSys 控制台   ·  网关在线 ●  :8080   ·  管理地址   │
│        [自动刷新 5秒▾] [手动刷新]            最近更新 xx:xx │
├─────────┬──────────────────────────────────────────────────┤
│ 侧边栏  │                    页面内容                        │
│ ● 概览   │                                                  │
│ ○ WAF安全防护                                               │
│ ○ 入网数据                                                  │
│ ▸ 组件   │                                                  │
│   防护 shield / 透传 trace / … / 结果 result                │
│ ▸ 服务   │                                                  │
│   配置服务 config / 注册 registry / 存储 object / 消息 mq   │
│ ○ 脚本   │                                                  │
│ ○ 全局配置（置底）                                          │
│ ○ 系统日志                                                  │
└─────────┴──────────────────────────────────────────────────┘
```

- **侧边栏**：图标 + 名称，当前页高亮；「组件 / 服务」为可折叠分组，激活项所在分组自动展开；组件与服务条目以「中文 + 英文」命名，点击直达对应详情页；WAF安全防护 / 入网数据紧跟概览，系统日志置于全局配置之后。
- **顶部工具条**：品牌名 + 版本号（与 `rocksys --version` 一致）、网关在线状态、管理地址、自动刷新间隔（关 / 5 秒 / 15 秒 / 30 秒）、手动刷新、最近更新时间。
- **登录**：管理接口绑定非回环地址时，进入控制台前需登录（账号密码），登录成功签发的 JWT 自动携带；回环地址本机免登录。

### 4.2 概览

目标：**30 秒完成巡检**。

```
┌─ 网关信息 ────────────────┐  ┌─ 运行指标（含趋势图）──────────┐
│ 监听端口   :8080           │  │ 每秒请求  延迟50%  延迟95%    │
│ 默认后端   http://…        │  │ 延迟99%  错误率 · 趋势折线    │
│ 转发超时   18 秒             │  └─────────────────────────────┘
└────────────────────────────┘
┌─ HTTP 数据流 ─────────────────────────────────────────────┐
│ Client → 入口 → [L1 防护: shield→trace→auth] →             │
│         → [L2 决策: dispatch→rewrite→script] → 转发引擎    │
│         → 后端 → [L3 结果: result→copy→obs] → Client       │
│ （节点=组件，内嵌启停开关+名称，点击名称跳组件页；             │
│   关闭组件灰化虚线，一眼看出链路缺口）                        │
└────────────────────────────────────────────────────────────┘
┌─ 服务状态总览 ────────────────────────────────────────────┐
│ [开关] 配置服务 config · 独立                              │
│ [开关] 注册 registry  · 独立                              │
│ …（4 个）                                                  │
└────────────────────────────────────────────────────────────┘
```

- **网关信息**：监听端口、默认后端、转发超时等基础信息，点击可进入全局配置页。
- **运行指标（原独立"指标"页合并至此）**：每秒请求数、延迟 50% / 95% / 99% 分位、错误率 + 每秒请求趋势折线图（按刷新周期累积采样）。观测未开启时显示引导。
- **HTTP 数据流**：按链路顺序展示组件（入口 → L1 防护 → L2 决策 → 转发引擎 → 后端 → L3 结果），**节点内嵌启停开关 + 中文/英文名**，点击名称跳组件详情页；关闭组件灰化虚线（一眼看出链路缺口），状态由开关直接体现。
- **服务状态总览**：4 个独立服务大卡片，**左上 switch 直接启停**（二次确认），点击名称跳服务详情页。

### 4.3 组件 / 服务（详情页）

目标：**一组件一页，状态与配置分页签**。

```
面包屑：概览 / 组件 / 防护 shield
┌─ 页面公共区域（面包屑下、页签上方）───────────────────────┐
│ [开关] 防护 shield  [入口环节]             [⟳ 刷新]        │
│ 入口安全防护：按 IP 黑白名单、WAF 规则与限流拦截请求…       │
├────────────────────────────────────────────────────────────┤
│ [状态] [配置(8)]                                            │
├────────────────────────────────────────────────────────────┤
│ 状态页签：                                                  │
│  启用时间 xx · 最近切换 xx · 状态：正常                      │
│  数据流位置：位于数据流「入口环节」…                         │
├────────────────────────────────────────────────────────────┤
│ 配置页签：该组件独有配置项（行内编辑，同全局配置风格）        │
└────────────────────────────────────────────────────────────┘
```

- **统一页签**：所有组件与服务详情页完全同构——默认「状态」页签，第二个「配置」页签（数量角标）；页签状态写入 URL（`?tab=config`），刷新不丢。
- **页面公共区域**：面包屑下方、页签上方统一承载启停开关 + 中文名/英文名 + 环节标签 + 组件描述，组件/服务页信息一眼可见。
- **状态页签**：运行信息卡片 = 启用时间 + 最近切换 + 状态消息 + 数据流位置示意（开关/名称/环节/描述已上移公共区域，不再重复）。
- **配置页签**：该组件/服务独有配置项（经 `COMPONENT_PREFIX` 过滤，复用配置渲染器）；无独立配置项的组件（如透传 trace、配置服务 config）显示空态引导；脚本组件附"去脚本页发布策略"链接。
- 启停交互：开启/关闭均二次确认，失败透出具体原因，操作后自动刷新。

### 4.4 全局配置

目标：**全局基础设施配置；组件与服务配置前往各自页面**。

```
├─ 分组标签: [网关] [数据访问] [其他] ─────────────────────┤
│ 网关                                                       │
│ 监听端口        8080                 [修改]               │
│ 默认后端        http://…             [修改]   ⚡已即时生效  │
│ …                                                         │
├─ 组件配置（链接卡片）────────────────────────────────────┤
│ 防护 shield · 黑白名单/限流/WAF   [8 项配置]  去配置 →    │
│ 透传 trace  · 链路标识           [无独立配置]  去配置 →   │
│ …（9 个数据流组件）                                       │
├─ 服务配置（链接卡片）────────────────────────────────────┤
│ 注册 registry · 服务注册与发现    [n 项配置]  去配置 →    │
│ …（4 个独立服务）                                         │
└───────────────────────────────────────────────────────────┘
```

- **排列顺序**：真正的全局配置（网关 / 数据访问 / 其他）在前，组件与服务配置入口链接卡片置后，避免遮挡常用全局项。
- **入口链接**：组件与服务各自的配置项已迁至对应详情页的「配置」页签，全局配置以链接卡片引导跳转。
- **保留分组**：仅网关（监听/后端/超时等底座项）、数据访问（DB_）、其他（无归属项）三类全局基础设施配置。
- 每项展示：配置名称、当前值、默认值、中文说明、示例；提供"恢复默认值"。
- **修改**：行内编辑 → 保存 → 提示"⚡ 已即时生效，无需重启"；热更即持久化（写回 `.env`）。
- 敏感项默认掩码；需重启才生效的项（如监听端口）置灰标注。

### 4.5 脚本

目标：**可视化管理策略脚本，发布与回滚**。

```
┌─ 脚本列表 ────────────────┐ ┌─ 编辑器 ───────────────────────────┐
│ 规则A        v3 ● 生效中    │ │ [规则A]  语法校验通过   [发布] [回滚] │
│ 规则B        v1 ● 生效中    │ │ ┌───────────────────────────────┐ │
│ (空)         -  ○ 未发布    │ │ │ -- 策略脚本                     │ │
│ [新建脚本]                  │ │ │ 当 访问路径 = "/拦截" 时        │ │
└───────────────────────────┘ │ │   返回 禁止访问                 │ │
  ▲ 版本时间线（点击回滚）     │ │ 结束                            │ │
  v3 ── 今天 10:12           │ └───────────────────────────────┘ │
  v2 ── 今天 09:40  ← 回滚到 │ [提示: 脚本只做策略控制，不改业务数据]  │
  v1 ── 昨天 18:00           └──────────────────────────────────────┘
```

交互流程：

1. 左侧脚本列表（名称 + 当前版本 + 生效状态）；支持新建命名脚本。
2. 编辑器支持脚本语法高亮与基础校验；顶部提示脚本只做策略控制。
3. **发布**：校验通过后发布 → 版本号 +1 → 列表刷新，提示"已发布 v3"。
4. **回滚**：在版本时间线选择目标版本 → 二次确认 → 生效版本回退；选择"移除"可将脚本下线。
5. 发布失败（语法不合法 / 含被禁能力）→ 明确提示原因，优先展示出错位置。

> **注意**：脚本保存在网关运行内存中，网关重启后需重新发布。回滚可选历史版本（仅限本次运行期内发布的版本）。

### 4.6 入网数据（原访问日志）

目标：**按时间范围与路径查看 HTTP 入网请求日志，定位单个请求**（与系统日志分开）。

```
┌─ 存储占用 ──────────────────────────────────────────────┐
│ 存储占用：文件日志 12.3 MB · 数据库表 4.0 MB · 总计 16.3 MB │
├─ 查询条件 ───────────────────────────────────────────────┤
│ 开始 [日期][时间]  结束 [日期][时间]  [查询]  [导出下载]   │
│ 路径精确 [/api/order/1]  路径模糊 [/api/order]  [重置]    │
│ 状态码 [全部▾]  耗时排序 [时间▾]  只看异常 [□]            │
├───────────────────────────────────────────────────────────┤
│ 时间          方法  路径            状态   耗时     ▶  │
│ 2026-08-05    GET   /api/order/1    200    12ms    ▶  │
│ 10:12:03      GET   /api/order/2    503    48ms    ▶  │
│ …                                                       │
└───────────────────────────────────────────────────────────┘
│ 点击行 ▶ 展开详情：请求来源、分环节耗时、转发目标、流量大小 │
```

- 按时间范围查询（日期 + 时间组合，精确到分；默认当天全天），支持导出下载。
- 支持路径精确 / 模糊过滤（后端查询）、状态码筛选、耗时排序、只看异常。
- 行点击展开详情：请求来源、路径与方法、状态码、防护 / 转发 / 总耗时分解、最终转发目标、请求与响应流量大小；负载扩展字段（如 `request_body`）自动平铺展示。
- 顶部展示日志存储占用（文件日志 + 数据库表独立统计并合计）。
- 某时段无日志自动跳过；整段为空时提示"所选时间范围无访问日志"。

### 4.7 系统日志（原运行日志）

目标：**系统进程实时日志查看**（ring buffer 实时监控，与 HTTP 入网数据日志分开）。URL 保持 `#/syslogs` 不变，仅菜单与页面标题改为「系统日志」。

## 5. 交互与界面规范

| 规范项 | 说明 |
|--------|------|
| 状态色 | 启用=绿；关闭=红；切换中=橙；提示=蓝 |
| 启停开关 | 滑动开关 + 二次确认；确认文案说明影响与降级结果 |
| 操作反馈 | 右上角提示条，成功 / 失败 / 警告三态；失败必须含具体原因 |
| 确认弹窗 | 居中弹窗，危险操作为红色按钮 |
| 表格 | 斑马纹、悬停高亮、列头固定；空数据给出引导 |
| 加载状态 | 首次打开骨架屏；刷新时按钮旋转；请求超时提示"管理接口不可达" |
| 空状态 | 说明原因 + 下一步操作（如"观测未开启，去开启"） |
| 数字格式 | 请求量千分位；延迟统一"毫秒"；时间统一"时:分:秒" / "年-月-日" |

**反馈闭环**：每次操作 = 确认 → 执行 → 成功 / 失败提示 → 自动刷新。绝不静默失败。

## 7. 视觉设计规范

### 7.1 主题

内置多主题切换，默认浅色（ElementUI 经典浅色）。切换入口在顶部工具条"主题"下拉框，选择结果保存于浏览器 `localStorage`（键 `rocksys.theme`），下次打开自动沿用；未保存时默认浅色。主题由 `html[data-theme]` 属性驱动，`webui/assets/js/theme.js` 负责持久化与绑定，`index.html` 头部的内联脚本在样式加载前应用主题以防止闪烁。

| 主题 | data-theme | 风格 |
|------|------------|------|
| 浅色（默认） | `light` | ElementUI 经典浅色（bg `#f5f7fa`、主交互 `#409eff`） |
| 深色 | `dark` | GitHub Dark 控制台风格（bg `#0d1117`、主交互 `#2f81f7`） |
| 护眼绿 | `green` | 豆沙绿护眼（bg `#c7edcc`、主交互 `#3f9d5a`） |

组件样式一律引用 `:root` 及各主题覆盖块中的语义化 CSS 变量（`--bg` / `--panel` / `--border` / `--text` / `--primary` 等），新增组件/页面时不得硬编码颜色，以保证任意主题下观感一致。深色主题色值如下：

| 色值 | 用途 |
|------|------|
| `#0d1117` | 页面背景 |
| `#161b22` | 面板 / 卡片 |
| `#1c212b` | 嵌套面板 / 表格斑马纹 |
| `#30363d` | 边框、分隔线 |
| `#e6edf3` | 主文字 |
| `#8b949e` | 次要文字 |
| `#2f81f7` | 主交互色（钢蓝） |
| `#22c55e` | 启用 / 成功 |
| `#f59e0b` | 切换中 / 警告 |
| `#ef4444` | 关闭 / 危险 / 错误 |

### 7.2 排版与间距

- 字号：正文 13px / 辅助 12px / 页面标题 16px / 指标数值 20px。
- 间距：4px 基数栅格；卡片内边距 16px；页面最大宽度 1280px 居中。
- 图标：统一简洁线形图标。

### 7.3 卡片设计

- 圆角 8px，细边框，悬停轻微上浮。
- 组件卡片：左上状态色点 + 名称，右上操作区；点击卡片主体可展开配置区。

## 8. 关键操作流程

### 8.1 开启一个组件

```
组件页 → 点击"开启" → 确认框"开启后将参与请求链路，规则立即生效"
→ 确认 → 提示"已启用" → 列表刷新（状态变绿）
失败 → 提示"开启失败：<具体原因>" → 状态不变
```

### 8.2 修改配置

```
配置页 → 选择组件分组 → 点击"修改" → 输入新值 → 保存
→ 提示"⚡ 已即时生效，无需重启" → 该项标记已更新
```

### 8.3 发布脚本并回滚

```
脚本页 → 编写内容 → 点击"发布" → 版本 +1，提示"已发布 v3"
→ 需要恢复 → 版本时间线选择旧版本 → 确认 → 生效版本回退
```

### 8.4 日常巡检

```
打开控制台 → 概览：网关是否在线？数据流组件是否异常关闭？请求量与错误率是否异常？
→ 异常追查：组件页调整启停 → 入网数据 / 系统日志页看指标与日志
```

## 9. 使用体验要求

| 项 | 要求 |
|----|------|
| 登录 | 管理接口绑定非回环地址时需先登录（账号密码）；凭证失效后跳转登录视图重新登录；回环地址本机免登录 |
| 自动刷新 | 概览 / 组件 / 服务 / WAF安全防护可设自动刷新（关 / 5 秒 / 15 秒 / 30 秒）；全局配置 / 脚本 / 日志手动刷新 |
| 网关不可达 | 顶部常驻提示"管理接口不可达"，页面保留上次数据并标注时间 |
| 浏览器 | 支持主流浏览器（Chrome / Edge / Firefox 较新版本） |
| 打开速度 | 首次打开即可使用，无外部资源依赖 |
| 数据安全 | 凭证仅保存在本机浏览器；敏感配置默认掩码 |
