## 2. 合理性评估

### 2.1 合理且高价值

1. **数据流图 + 组件穿插**：组件本质是链中间件，Head→Middle→Tail 顺序是核心语义；现状小卡片无法表达"组件在链路哪一环、关了影响什么"。已有 `docs/HTTP_DATAFLOW.md` 权威图可落地为静态 CSS/SVG 渲染（符合"无第三方库"约束）。图只展示状态色点 + 跳转、开关放卡片，避免图内交互拥挤，交互边界清晰。
2. **卡片带开关直启**：启停是最高频操作，现状需 3 步；首页直开降为 1 步。**保留二次确认**（产品原则 §3）。
3. **独立服务迁出组件**：config/registry/object/mq 与数据流无关，混排误导用户；二分（链中间件 vs 独立服务）正确。
4. **组件页页签化**：一组件一页 + 「状态/配置」页签统一所有组件模板，解决"全部混在一起、配置很丑"；页签比点击展开更符合"配置是独立一级信息"的认知，且所有组件行为一致、学习成本低。
5. **全局配置瘦身为基础设施**：组件/服务配置各自归位后，全局配置只剩网关 + 数据访问 + 其他，定位清晰（全局基础设施），与"全局配置"之名相符。
6. **观测分裂**：原"观测"混三种心智（实时监控/事后排查/安全告警）；分裂后语义清晰。

### 2.2 风险与代价

1. **首页过载**：网关信息 + 指标 + 趋势图 + 数据流图 + 组件/服务总览 + 降级链一屏难容。需信息分区（两列布局 + 卡片分区），避免违背"30 秒一眼看清"。
2. **侧边栏变长**：组件（9 项）+ 服务（4 项）+ 观测（3 项）+ 全局配置。分组默认折叠；激活项所在组自动展开；菜单项「中文 + 小号英文」紧凑排版。
3. **指标合并的迁移面**：`main.js` 路由、自动刷新白名单、`store.metricsHistory` 采样（240 条）、趋势图绘制时机（resize/刷新生命周期）需随 overview 一并处理。
4. **全局配置变空风险**：只剩网关/数据访问/其他 3 组，需以"分组 + 链接卡片"填充组件入口，避免空页面感。
5. **trace / config 无配置项**：trace 组件与 config 服务无专属前缀（无 TRACE_/CONFIG_），配置页签需空态引导，避免"空白页"。

## 3. 用户体验评估

| 维度 | 结论 |
|---|---|
| 心智模型 | 组件 = 数据流环节上的能力节点，服务 = 独立支撑系统，全局配置 = 全局基础设施，三层各归其位 |

## 4. 目标信息架构

```
概览          网关信息 · 运行指标(+趋势图) · HTTP数据流图 · 组件状态总览(卡片带开关) · 服务状态总览 · 降级链
组件
  防护 shield / 透传 trace / 认证 auth / 分发 dispatch / 改写 rewrite / 脚本 script / 观测 obs / 抄送 copy / 结果 result
服务
  配置服务 config / 注册 registry / 存储 object / 消息 mq
脚本           （不变）
观测
  WAF安全防护（原拦截统计） / 入网数据（原访问日志） / 系统日志（原运行日志）
全局配置      网关 · 数据访问 · 其他；组件/服务配置项 → 链接跳对应页
```

## 7. 已确认采纳的交互优化（实施必须遵循）

1. **首页数据流图**：关闭的组件节点灰化 + 连线改虚线，一眼看出"链路缺口在哪一环"；节点 hover 显示组件说明与状态；点击跳组件页。
2. **首页卡片热区分离**：左上开关与卡片主体（名称点击跳转）明确分离，避免误触；开关操作保留二次确认。
3. **页签记忆**：组件/服务页当前页签写入 URL（`?tab=config`），刷新/分享不丢。
4. **面包屑**：概览 > 组件 > 防护 shield，多级菜单下帮助定位。
5. **script 组件配置页签**：附「去脚本页发布策略」链接（脚本内容在脚本菜单管理），避免用户找不到发布入口。
6. **配置空态**：trace/config 等无配置项组件，配置页签显示"该组件无独立配置项"及说明，不出现空白页。
7. **观测 URL 稳定**：三页仅改菜单文案/标题，URL 不变，旧收藏与外部链接不失效。
8. **自动刷新**：overview 已支持；组件/服务页开关状态跟随自动刷新（复用现有周期）。
9. **侧边栏**：激活项所在分组自动展开，其余折叠；组件/服务子项「中文 + 小号英文」紧凑排版。
10. **全局配置**：链接卡片式入口（每行：组件名 + 说明 + 去配置按钮），网关/数据访问保留原 tab 编辑能力。
11. **首页分区**：网关信息 + 指标/趋势 一行两列；数据流图独立整行卡片；组件/服务总览两列并排；降级链保留。避免单列过长。
12. **迁移零破坏**：组件/服务页与全局配置共用 `store.configList` 单一数据源与 `configEditor` 渲染器，改配置任何入口即时同步。
